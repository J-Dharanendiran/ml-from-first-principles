# ➗ When the Answer Is a Number: The Voting Regressor

> *"You can't count votes for ₹47 lakh, ₹52 lakh, and ₹49 lakh. But you can average them."* 🏠

In the last three chapters, the crowd voted on **labels**: cat or dog, class 0 or class 1, yes or no. Then the lecture changes the question.

> 🤔 *"What if my model doesn't predict a class? What if it predicts a number, like a house price?"*

Same crowd. Same core idea. A different way of counting.

---

## 🏠 Why "Majority Vote" Stops Making Sense

Classification looks like this:

```text
Model 1 → Class A
Model 2 → Class B
Model 3 → Class A

Final → Class A
```

Regression predicts a **continuous numerical value**. Suppose the actual house price is ₹50 lakh:

```text
Actual house price = ₹50 lakh

Model 1 → ₹47 lakh
Model 2 → ₹52 lakh
Model 3 → ₹49 lakh
```

Try to hold an election:

```text
₹47 lakh → 1 vote
₹52 lakh → 1 vote
₹49 lakh → 1 vote
```

There is no majority and no winner. The votes are all different numbers.

So instead you combine the numbers themselves, usually by taking their **average**. The lecture introduces this as multiple regression models trained on the same dataset, whose predictions for a new point are combined by their **mean**.

---

## 🧮 The Basic Recipe

Train three regression models on the same training data $D$:

$$
D \rightarrow M_1 \qquad D \rightarrow M_2 \qquad D \rightarrow M_3
$$

A new input $x$ arrives. Each model predicts:

$$
\hat y_1, \; \hat y_2, \; \hat y_3
$$

The Voting Regressor combines them:

$$
\boxed{\hat y_{\text{final}} = \frac{\hat y_1 + \hat y_2 + \hat y_3}{3}}
$$

### A quick example

```text
Linear Regression → 100
SVR               → 110
Decision Tree     → 105
```

$$
\hat y_{\text{final}} = \frac{100 + 110 + 105}{3} = \frac{315}{3} = 105
$$

$$
\boxed{105}
$$

### ✅ Sanity Check

100 + 110 = 210, plus 105 = **315**. 315 ÷ 3 = **105**. ✔️

---

## 🎯 Why Should Averaging Help At All?

> 🤔 *"Why would the average of three guesses beat picking one of them?"*

Suppose the true value is **100**, and the models predict:

```text
Model 1 → 95    (error −5)
Model 2 → 105   (error +5)
Model 3 → 100   (error  0)
```

$$
\frac{95 + 105 + 100}{3} = \frac{300}{3} = 100
$$

The positive and negative errors **cancel**. One model overestimates, another underestimates, another is close, and the average lands nearer the truth than the worst of them.

---

## 🎨 Diversity Returns

You've heard this refrain in every chapter, and here it is again. You don't merely want several models; you want models that **behave differently**.

```text
Model 1 → Linear Regression
Model 2 → SVR
Model 3 → Decision Tree
```

These use very different mechanisms to predict, so their errors can differ.

**A case where diversity pays:**

```text
Actual = 100

Linear Regression → 90
SVR               → 108
Decision Tree     → 102

Average = (90 + 108 + 102) / 3 = 300 / 3 = 100  ✅
```

**A case where it doesn't:**

```text
90
90
90

Average = 90
```

No magic happened. Three models simply agreed on the same mistake.

$$
\boxed{\text{Good ensemble} \approx \text{good models} + \text{useful diversity}}
$$

> 🤔 *"So is the combined curve literally drawn halfway between the two lines?"*

Not in a strict geometric sense. What actually happens is **prediction by prediction**: for each input, the two numerical outputs are averaged. The result tends to land between the two, so the ensemble borrows some behavior from each model.

### Why add another algorithm?

Because one model can fail in one region of the input space where another works better:

| Model | Strength |
|---|---|
| **Linear Regression** | Captures broad linear trends |
| **SVR** | Can capture nonlinear relationships |
| **Decision Tree** | Captures nonlinear structure through recursive splits |

Their errors may differ, and different errors are what averaging feeds on.

The lecture shows that adding models can change the fitted function and *potentially* improve the metric. It also shows that **improvement isn't guaranteed**.

## 💻 Now the Machinery: `VotingRegressor`

For classification you used `VotingClassifier`. For regression:

```python
from sklearn.ensemble import VotingRegressor

vr = VotingRegressor(
    estimators=[
        ("lr",  lr),
        ("svr", svr),
        ("dt",  dt)
    ]
)

vr.fit(X_train, y_train)
y_pred = vr.predict(X_test)
```

> 🤔 *"Where's the `voting="hard"` or `voting="soft"` argument?"*

There isn't one, and the reason is worth a beat. Hard and soft voting are about **class labels and class probabilities**. Regression has no classes, so it naturally averages continuous predictions. Classification counts votes; regression averages numbers.

The `estimators` list is the same shape as before: `(name, model)` pairs.

```python
("lr", LinearRegression())
#  ↑           ↑
# name      the model object
```

## 🤝 A Bad Model Isn't Automatically Useless (But Don't Abuse That)

The lecture makes a subtle point: a model performing badly by itself shouldn't be **ignored immediately**. What matters for an ensemble isn't only individual performance but also the **relationship between the errors**:

$$
\text{individual performance} \quad \text{and} \quad \text{relationship between errors}
$$

A mediocre model can sometimes contribute useful diversity. That does **not** mean you should throw terrible models into every ensemble and hope. The candidates still need to be sensible.

## 🔁 The Same Trick as Before: Same Algorithm, Different Settings

You don't need three different algorithms. The lecture again shows the second construction strategy from the classification chapter: **several versions of one algorithm with different hyperparameters.**

```text
SVR 1 → C=1,   gamma=0.1
SVR 2 → C=10,  gamma=0.1
SVR 3 → C=10,  gamma=1
SVR 4 → C=100, gamma=0.01
```

These are technically the same algorithm but different trained models. *(The specific values are my illustration; the lecture says the idea, not these numbers.)*

> 🤔 *"Why would different hyperparameters make the models differ?"*

Because hyperparameters change how the model behaves. For an SVR:

- **`C`** affects the penalty for errors
- **`gamma`** controls the influence of individual training points for RBF-type kernels
- **`kernel`** determines the transformation the model uses

Different settings → different fitted functions → different predictions:

```text
SVR configuration A → Prediction A ┐
SVR configuration B → Prediction B ├→ Average → Final prediction
SVR configuration C → Prediction C ┘
```

A tiny same-algorithm example:

```text
SVR #1 → 101
SVR #2 → 97
SVR #3 → 103
SVR #4 → 99
SVR #5 → 100
```

$$
\frac{101 + 97 + 103 + 99 + 100}{5} = \frac{500}{5} = 100
$$

In code, the lecture builds the ensemble from a list of configurations:

```python
models = [
    SVR(C=1,   gamma=0.1),
    SVR(C=10,  gamma=0.1),
    SVR(C=10,  gamma=1),
    SVR(C=100, gamma=0.01)
]

vr = VotingRegressor(
    estimators=[
        ("svr1", models[0]),
        ("svr2", models[1]),
        ("svr3", models[2]),
        ("svr4", models[3])
    ]
)
```

## 🥊 Voting vs Hyperparameter Tuning: Two Different Philosophies

> 🤔 *"Why not just use GridSearchCV and pick the best SVR?"*

Both are valid, but they ask different questions.

| | **Hyperparameter tuning** | **Voting ensemble** |
|---|---|---|
| Question | "Which configuration should survive?" | "Why not let several configurations contribute?" |
| Outcome | **Select** one best model | **Combine** multiple models |

The lecture presents the second as an extension of the voting idea.

---

## ☠️ The Danger of Averaging Everything

Combining everything is **not** automatically good. Suppose:

```text
Model A → excellent   → 100
Model B → excellent   → 102
Model C → awful       →  50
Model D → awful       →  48
```

$$
\frac{100 + 102 + 50 + 48}{4} = \frac{300}{4} = 75
$$

If the truth is around 100, that's terrible. Or in the smaller version:

```text
Best model → 100
Weak models → 70, 70

Average = (100 + 70 + 70) / 3 = 240 / 3 = 80   ← worse than the best model
```

$$
\boxed{\text{More estimators} \neq \text{automatically better ensemble}}
$$

Averaging shines when the models have **complementary errors**, not when one excellent model is dragged down by poor ones. That's why the lecture recommends experimenting with combinations instead of assuming one always wins.

## 🌊 Smoothing: How One Extreme Guess Gets Diluted

```text
Model 1 → 70
Model 2 → 100
Model 3 → 102
```

$$
\frac{70 + 100 + 102}{3} = \frac{272}{3} \approx 90.67
$$

The extreme prediction of 70 gets pulled toward the others. This is one reason averaging can reduce variance when the models' errors aren't perfectly correlated.

## 📐 The Statistical Heart: Why Errors Cancel

Model $i$ predicts the true value $y$ plus an error $\epsilon_i$:

$$
\hat y_i = y + \epsilon_i
$$

The ensemble averages $M$ predictions:

$$
\hat y_{\text{ensemble}} = \frac{1}{M} \sum_{i=1}^{M} (y + \epsilon_i) = y + \frac{1}{M} \sum_{i=1}^{M} \epsilon_i
$$

So the ensemble's error is simply the **average of the individual errors**:

$$
\boxed{\epsilon_{\text{ensemble}} = \frac{1}{M} \sum_{i=1}^{M} \epsilon_i}
$$

### Case 1: errors point in different directions

```text
Model 1 error = −10
Model 2 error = +8
Model 3 error = +2

Ensemble error = (−10 + 8 + 2) / 3 = 0
```

Perfect cancellation.

### Case 2: all errors are identical

```text
Model 1 → +10
Model 2 → +10
Model 3 → +10

Ensemble error = (10 + 10 + 10) / 3 = 10
```

Nothing cancels.

$$
\text{Low error correlation} \Rightarrow \text{greater potential benefit from averaging}
$$

$$
\text{Highly correlated errors} \Rightarrow \text{less benefit}
$$

This is the very same principle as the 70% classifier calculation, now in numerical form.

### One thing you can be sure of

Averaging can never make the *size* of the ensemble error larger than the *average size* of the individual errors:

$$
\left| \frac{1}{M} \sum_i \epsilon_i \right| \;\le\; \frac{1}{M} \sum_i |\epsilon_i|
$$

That's the triangle inequality. But notice what it does **not** say: the ensemble can still be worse than your *best* single model, as the "awful models" example showed.

## 🧾 The Full Regression Workflow

```text
                  Dataset
                     │
                     ↓
              Split X and y
                     │
                     ↓
        ┌────────────┼────────────┐
        ↓            ↓            ↓
      Model 1      Model 2      Model 3
        ↓            ↓            ↓
     prediction   prediction   prediction
        │            │            │
        └────────────┼────────────┘
                     ↓
                  Average
                     ↓
             Final prediction
```

$$
\boxed{\hat y = \frac{1}{M} \sum_{i=1}^{M} \hat y_i}
$$

where $M$ is the number of models and $\hat y_i$ is the prediction from model $i$.

### A clean implementation

```python
from sklearn.linear_model import LinearRegression
from sklearn.svm import SVR
from sklearn.tree import DecisionTreeRegressor
from sklearn.ensemble import VotingRegressor

lr  = LinearRegression()
svr = SVR(kernel="rbf")
dt  = DecisionTreeRegressor(random_state=42)

voting_reg = VotingRegressor(
    estimators=[("lr", lr), ("svr", svr), ("dt", dt)]
)

voting_reg.fit(X_train, y_train)
y_pred = voting_reg.predict(X_test)
```

Then evaluate:

```python
from sklearn.metrics import mean_squared_error, r2_score

mse = mean_squared_error(y_test, y_pred)
r2  = r2_score(y_test, y_pred)

print("MSE:", mse)
print("R²:", r2)
```

### What happens inside `fit` and `predict`

```text
fit(X_train, y_train)

                X_train, y_train
                       │
       ┌───────────────┼────────────────┐
       ↓               ↓                ↓
Linear Regression     SVR       Decision Tree
       │               │                │
       ↓               ↓                ↓
    Model 1         Model 2          Model 3
```

`predict(X_test)` averages **column by column** (one column per test sample):

```text
Model 1 → [100, 105, 110]
Model 2 → [102, 100, 108]
Model 3 → [ 98, 103, 112]

Sample 1: (100 + 102 + 98)  / 3 = 300 / 3 = 100
Sample 2: (105 + 100 + 103) / 3 = 308 / 3 ≈ 102.67
Sample 3: (110 + 108 + 112) / 3 = 330 / 3 = 110

Final output → [100, 102.67, 110]
```

## 🔗 ML Bridge: Where This Lands in Your Work

Your Stroke Prediction system is a classification problem, so `VotingClassifier` is the tool that fits it directly. This chapter matters for the **next regression problem** you build. A practical checklist:

1. Evaluate Linear Regression, SVR, and a Decision Tree **separately** first.
2. Build a `VotingRegressor` from the sensible ones.
3. Compare on held-out data (not training data), and keep the ensemble only if it beats your best single model.

---

## 🌀 Deepest Realization

> **Voting for labels counts hands; voting for numbers averages guesses. In both cases the crowd helps only because its mistakes point in different directions.**

The line `VotingRegressor(...)` is the easy part. The idea underneath is one equation: the ensemble's error is the *average* of the members' errors, so errors that disagree cancel and errors that agree survive.

---

## ✅ Final Takeaway

> *"To ensemble numbers, average them; to make that worthwhile, choose models whose errors disagree, test each one alone first, and let held-out data decide."* ➗
