# 🎯 The Faster Ruler

> *"Entropy and Gini are asking the exact same question. One of them just refuses to use logarithms to answer it."*

---

You now have a complete mechanism for building a tree: Entropy measures impurity, Information Gain measures how much a split reduces it, and the tree picks whichever feature maximizes that reduction. That mechanism works. But it isn't the only one. There's a second splitting criterion that answers the *same* question, using different arithmetic — **Gini Impurity**.

> **Which split produces the purest child nodes?**

Both Entropy and Gini exist to answer exactly that. They're not competing philosophies — they're two rulers measuring the same thing.

## 🔀 Same Procedure, Swapped Ruler

Recall the Entropy pipeline from the last two chapters:

```
Parent Entropy
      ↓
Try a feature
      ↓
Child Entropies
      ↓
Weighted Child Entropy
      ↓
Information Gain
      ↓
Choose highest Information Gain
```

Gini follows the *identical* shape — only the impurity formula changes:

```
             Decision Tree
                  |
          Need a good split
                  |
        ┌─────────┴─────────┐
        ↓                   ↓
     Entropy             Gini
        ↓                   ↓
 Information Gain       Gini reduction
```

Same skeleton. Different muscle.

## 📐 The Formula

$$
\boxed{Gini = 1 - \sum_{i=1}^{c} P_i^2}
$$

For binary classification:

$$
\boxed{Gini = 1 - (P_+^2 + P_-^2)}
$$

No logarithm anywhere. Just squares, a sum, and a subtraction from 1.

## 🟢 The Two Extremes, Worked

**A completely pure node** — all `Yes`:
$$
P(Yes) = 1, \quad P(No) = 0
$$
$$
Gini = 1 - (1^2 + 0^2) = 1 - 1 = \boxed{0}
$$

Exactly what you'd expect — same zero-impurity behavior as Entropy.

**A perfectly mixed node** — 3 Yes, 3 No:
$$
P(Yes) = P(No) = 0.5
$$
$$
Gini = 1 - (0.5^2 + 0.5^2) = 1 - (0.25 + 0.25) = 1 - 0.5 = \boxed{0.5}
$$

So for binary classification:
```
Pure node       → Gini = 0
50/50 mixture   → Gini = 0.5
```

> *"Wait — Entropy maxes out at 1, but Gini only reaches 0.5? Are they not comparable?"*

Correct catch. They're not directly comparable, and this trips people up constantly.

$$
\boxed{0 \leq Gini \leq 0.5} \qquad \text{vs.} \qquad \boxed{0 \leq Entropy \leq 1}
$$

**Do not compare raw values of Entropy and Gini directly.** Seeing "Entropy = 0.5" and "Gini = 0.5" side by side does *not* mean they represent the same amount of impurity — they're on different scales entirely.

| 0.0 | 1.0 | 0 | 0 |

```

```

Plotted, both curves are the same inverted-U shape, just scaled differently:

```
Entropy                          Gini
  1 |      ●                    0.5 |      ●
    |    /   \                      |    /   \
    |  /       \                    |  /       \
  0 | ●---------●                 0 | ●---------●
    +--------------→                +--------------→
      0    0.5    1                   0    0.5    1
```

## ⚙️ Why Gini Is Computationally Cheaper

This is the actual reason Gini exists as an alternative rather than a redundant twin.

**Entropy's pipeline:**
```
P → log(P) → P×log(P) → Sum → negative
```

**Gini's pipeline:**
```
P → P² → Sum → 1 −
```

Squaring is just multiplication. Logarithms are inherently more expensive to compute. So for probabilities like $0.4$ and $0.6$:

- **Gini:** $1 - (0.4^2 + 0.6^2)$ — pure arithmetic.
- **Entropy:** $-(0.4\log_2 0.4 + 0.6\log_2 0.6)$ — requires evaluating a logarithm twice.

At the scale of building trees over large datasets with thousands of candidate splits, that difference compounds fast.

## 🎾 Applying Gini to Play Tennis

Same dataset, same 14 rows, same goal — but now with Gini as the ruler instead of Entropy.

### Step 1 — Parent Gini

```
Yes = 9, No = 5, Total = 14
```
$$
P(Yes) = \frac{9}{14} \approx 0.6429, \qquad P(No) = \frac{5}{14} \approx 0.3571
$$

$$
Gini = 1 - \left[\left(\frac{9}{14}\right)^2 + \left(\frac{5}{14}\right)^2\right]
$$

$$
\left(\frac{9}{14}\right)^2 \approx 0.4133, \qquad \left(\frac{5}{14}\right)^2 \approx 0.1276
$$

$$
Gini = 1 - (0.4133 + 0.1276) = 1 - 0.5408
$$

$$
\boxed{Gini(Parent) \approx 0.4592}
$$

### Step 2 — Gini for the `Outlook` Split

Using the same three groups as before:

| Outlook | Yes | No | Total |
|---|---:|---:|---:|
| Sunny | 2 | 3 | 5 |
| Overcast | 4 | 0 | 4 |
| Rainy | 3 | 2 | 5 |

**Sunny:** $P(Yes)=0.4,\ P(No)=0.6$
$$
Gini(Sunny) = 1 - (0.4^2 + 0.6^2) = 1 - (0.16+0.36) = \boxed{0.48}
$$

**Overcast:** $P(Yes)=1,\ P(No)=0$
$$
Gini(Overcast) = 1 - (1^2 + 0^2) = \boxed{0}
$$
Perfectly pure — same as it was under Entropy.

**Rainy:** $P(Yes)=0.6,\ P(No)=0.4$
$$
Gini(Rainy) = 1 - (0.6^2 + 0.4^2) = 1 - (0.36+0.16) = \boxed{0.48}
$$

### Step 3 — Weighted Gini After the Split

Same weighting logic as weighted Entropy — bigger children count for more:

$$
WeightedGini(Outlook) = \frac{5}{14}(0.48) + \frac{4}{14}(0) + \frac{5}{14}(0.48)
$$
$$
= 0.1714 + 0 + 0.1714
$$
$$
\boxed{WeightedGini(Outlook) \approx 0.3429}
$$

### Step 4 — Gini Reduction

$$
GiniReduction = Gini(Parent) - WeightedGini(Outlook) = 0.4592 - 0.3429
$$
$$
\boxed{GiniReduction \approx 0.1163}
$$

Splitting on `Outlook` reduces Gini impurity by roughly **0.1163** — the direct Gini analog of Information Gain.

## 🩺 Sanity Check

| | Entropy | Gini Impurity |
|---|---|---|
| **Formula** | $-\sum P_i \log_2 P_i$ | $1 - \sum P_i^2$ |
| **Binary minimum** | 0 | 0 |
| **Binary maximum** | 1 | 0.5 |
| **Uses logarithm?** | Yes | No |
| **Uses squaring?** | No | Yes |
| **Computational cost** | Higher | Lower |
| **General behavior** | Inverted-U | Inverted-U (same shape) |

And the naming convention to keep straight:

```
Entropy  → the reduction is called "Information Gain"
Gini     → the reduction is called "Gini Reduction" (or "decrease in Gini impurity")
```

Both ultimately compute the same underlying thing:

$$
\boxed{\text{Impurity before} - \text{Weighted impurity after}}
$$

## 🌉 ML Bridge

Because Entropy and Gini both reward purity, they usually — but not always — agree on which feature is "best." A feature with the highest Information Gain will *often* also have the highest Gini Reduction, so the resulting trees are frequently similar, sometimes identical. But they're not mathematically equivalent measures, and on some datasets they genuinely disagree, favoring different features or producing differently balanced trees. That's why libraries like scikit-learn expose the criterion as a *choice* (`gini`, `entropy`, `log_loss` in `DecisionTreeClassifier`) rather than hard-coding one — Gini is the default in practice mainly because it's cheaper to compute at scale, not because it's "more correct."

## 🌀 Deepest Realization

Gini can be read as something more concrete than an abstract impurity score: it's the probability of **misclassifying** a randomly picked point if you assigned it a label by randomly sampling from the node's own class distribution. At $P=0.5$, guessing randomly gets you wrong exactly half the time — hence $Gini=0.5$, the ceiling. At $P=1$, there's only one label to guess, so you're never wrong — hence $Gini=0$. Entropy was measuring *how much you don't know*; Gini is measuring *how often that not-knowing would burn you*. Different question, same answer about which splits are good.

## ✅ Final Takeaway

> *"The tree isn't choosing a feature because it 'likes' Outlook or Humidity — it's mathematically comparing candidate splits under whichever impurity measure it's using, Entropy or Gini, and picking whichever produces the largest reduction in impurity. Gini asks the same question as Entropy, answers it with squares instead of logarithms, tops out at 0.5 instead of 1 for binary problems, and is computationally cheaper — which is exactly why it's the more common default in practice."*
