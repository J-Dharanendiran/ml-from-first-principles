# 📉 Performing Gradient Descent for Two Variables ($m$ and $b$)

When transitioning from optimizing a single parameter (where the slope $m$ was assumed to be a known constant and only the intercept $b$ was updated) to a fully functional linear regression model, we must optimize both the slope ($m$) and the intercept ($b$) simultaneously.

To achieve this, Gradient Descent relies on calculating partial derivatives. Because our loss function depends on two changing variables ($m$ and $b$), we can no longer calculate a simple single-variable derivative. Instead, we calculate the **Gradient**—a vector of partial derivatives that points in the direction of the steepest ascent on the loss surface.

---

## 1️⃣ Step 1: Defining the Loss Function

Our starting point is the Mean Squared Error (or Sum of Squared Residuals) loss function ($L$), which is mathematically represented as:

$$L = \sum_{i=1}^{n} (y_i - \hat{y}_i)^2$$

Since $\hat{y}_i = m x_i + b$, we substitute this back into the equation:

$$L = \sum_{i=1}^{n} (y_i - m x_i - b)^2$$

Here, $y_i$ (actual values) and $x_i$ (input features) are fixed constants from our training dataset. The loss function $L$ is a multi-variable function that changes dynamically based on the tuning of the parameters $m$ and $b$.

---

## 2️⃣ Step 2: Deriving the Partial Derivatives (The Slopes)

To find how the loss function changes with respect to each parameter individually, we compute the partial derivatives using the mathematical chain rule.

### 📐 1. Partial Derivative with respect to $b$ ($\frac{\partial L}{\partial b}$)

When differentiating with respect to $b$, we treat $m$ as a constant.

- Applying the power rule to the outer term, the exponent ($2$) is brought to the front.
- We then multiply by the derivative of the inner term $(y_i - m x_i - b)$ with respect to $b$. Since $y_i$ and $m x_i$ are treated as constants, their derivatives are $0$, and the derivative of $-b$ is $-1$.
- Multiplying these together yields:

$$\frac{\partial L}{\partial b} = -2 \sum_{i=1}^{n} (y_i - m x_i - b)$$

### 📏 2. Partial Derivative with respect to $m$ ($\frac{\partial L}{\partial m}$)

When differentiating with respect to $m$, we treat $b$ as a constant.

- Applying the power rule, the exponent ($2$) is brought to the front.
- We then multiply by the derivative of the inner term $(y_i - m x_i - b)$ with respect to $m$. Since $y_i$ and $b$ are treated as constants, their derivatives are $0$, and the derivative of $-m x_i$ with respect to $m$ is $-x_i$.
- Multiplying these together yields:

$$\frac{\partial L}{\partial m} = -2 \sum_{i=1}^{n} (y_i - m x_i - b) x_i$$

---

## 3️⃣ Step 3: The Simultaneous Update Equations

At each training epoch (iteration), both parameters must be updated at the exact same time. If you update $b$ first and use the new $b$ to calculate the slope for $m$, you violate the mathematical integrity of the gradient vector at that specific point.

The update rules are formulated as:

$$b_{\text{new}} = b_{\text{old}} - (\eta \times \frac{\partial L}{\partial b})$$

$$m_{\text{new}} = m_{\text{old}} - (\eta \times \frac{\partial L}{\partial m})$$

*(Where $\eta$ is the learning rate)*

In code, this is implemented within a loop over the specified number of epochs:

1. **Calculate the current slopes** for the entire batch of data:
   ```python
   slope_b = -2 * np.sum(y - m * x - b)
   slope_m = -2 * np.sum((y - m * x - b) * x)
   ```
2. **Update the parameters** simultaneously:
   ```python
   b = b - (learning_rate * slope_b)
   m = m - (learning_rate * slope_m)
   ```

This iterative loop continues until the parameters stabilize (converge) near the optimal values.

# 🎥 Visualisation of Two-Variable Gradient Descent

Visualising Gradient Descent in a two-variable space requires moving from simple 2D curves to 3D surfaces and contour projections. The video demonstrates several highly intuitive plots that map this journey.

## 📈 1. 2D Regression Line Convergence

This visualization overlays the changing regression line on top of the actual dataset scatter plot across epochs.

- **The Starting Point:** The model is initialized with highly inaccurate random parameters—for instance, starting with a slope $m = 100$ (or even $600$) and an intercept $b = -120$. At this stage, the green regression line is extremely far from the data points.
- **The Transition:** As the epochs progress, you watch the line dynamically rotate (adjusting its slope $m$) and slide up or down (adjusting its intercept $b$).
- **The Convergence:** Within a set number of epochs (e.g., 30 to 50 epochs), the line perfectly settles on top of the red "optimal OLS baseline" line, demonstrating that the algorithm successfully finds the best fit line regardless of how poor the initial starting parameters were.

## 🥣 2. The 3D Loss Surface Plot (The Bowl)

When mapping the total loss against both $m$ and $b$, the graph forms a 3D parabolic surface, resembling a giant, smooth bowl.

- **The Axes:** The horizontal $x$-axis represents the slope $m$, the horizontal $y$-axis represents the intercept $b$, and the vertical $z$-axis represents the total Cost (Loss).
- **The Path of Descent:** The initial random parameters place the model at some high-altitude point on the outer wall of this 3D bowl.
- **The Descent:** As Gradient Descent runs, the updates trace a sequence of dots (steps) that "walk" down the steep inner walls of the bowl. The step sizes are massive when the walls are steep and narrow down to tiny, microscopic movements as the path reaches the flat valley at the very bottom. This bottom point is the global minimum where the error is minimized.

## 🎯 3. 2D Contour Plots (Concentric Rings)

Because rotating and viewing a 3D surface can be computationally heavy and difficult to analyze, we can project the 3D bowl down into a 2D representation called a **Contour Plot**.

- **How it Works:** The $x$-axis of this plot is the slope $m$, and the $y$-axis is the intercept $b$. Concentric rings are drawn to represent the height (the loss). Rings on the outside represent high loss values (steep mountain walls), while the concentric rings get tighter as they approach the center, which represents the lowest loss (the valley).
- **The Trajectory:** This visualization plots a clear line of steps starting from an extreme outer coordinate (e.g., $m = -100$, $b = 120$). You can see the trajectory cutting directly across the rings towards the center.
- **Automatic Step Scaling:** The spacing between the plotted points on the trajectory shows large gaps initially, which rapidly shrink as the path nears the center. This visually proves the mathematical elegance of Gradient Descent: it naturally takes fast, aggressive steps when far from the solution, but slows down to ensure a precise, stable landing at the exact center (the global minimum).

## ⏱️ 4. Individual Parameter and Cost Tracking over Epochs

To round out the visual suite, three separate graphs plot the metrics directly against the Epoch number on the $x$-axis:

- **Cost vs. Epochs:** Shows a steep drop in error over the first few iterations, which gradually curves and flattens into a horizontal line, signaling that the model has fully trained and further epochs are unnecessary.
- **$b$ vs. Epochs & $m$ vs. Epochs:** These track the physical parameter values. For instance, $m$ starts at $-100$ and smoothly climbs until it stabilizes flatly at its mathematically correct OLS value of approximately $27.2$. These horizontal plateaus confirm the algorithm has converged.

# 🔬 Deeper Walkthrough: From One Unknown to Two Unknowns

Until now, we cheated a little. When we optimized only $b$, we already knew the correct slope $m$. That isn't how Linear Regression works in reality — both the slope and the intercept are unknown. The model must discover both simultaneously.

This changes everything. Instead of moving on a line, Gradient Descent now moves across an entire surface.

## 1️⃣ From One Unknown to Two Unknowns

Earlier we had:

$$y = mx + b$$

Suppose $m = 78.35$ was already known. Then the only unknown was $b$, and Gradient Descent only had one job: move $b$ until the loss became minimum. The graph looked like a simple parabola — easy.

Now imagine nobody tells you $m$ or $b$. Both are unknown. The model must answer *how steep should the line be?* and *where should the line sit vertically?* at the same time.

## 2️⃣ Why the Loss Function Changes

Our prediction equation is:

$$\hat{y} = mx + b$$

Our loss remains:

$$L = \sum (y - \hat{y})^2$$

Substituting $\hat{y} = mx + b$:

$$L = \sum (y - mx - b)^2$$

Previously, loss depended only on $b$. Now, loss depends on $m$ *and* $b$. It is now a function $L(m, b)$ instead of $L(b)$. That small notation change completely changes the geometry.

With one variable, the loss is a curve. With two variables, the loss has width, depth, and height — it becomes a surface.

## 3️⃣ Why Ordinary Derivatives No Longer Work

Previously we asked "what is the slope?" — easy, there was only one direction: left or right.

Now imagine standing on a mountain. You can walk north, south, east, west, northeast, or southwest. The question "what is the slope?" no longer makes sense on its own — slope depends on which direction you're facing.

This is exactly why partial derivatives exist.

## 4️⃣ What is a Partial Derivative?

Suppose Loss depends on $m$ and $b$. To know how Loss changes when changing only $b$, we freeze $m$ — like pressing a pause button. Then we compute $\frac{\partial L}{\partial b}$. This tells us: *if I only move $b$, how much does the loss change?*

Now freeze $b$, move only $m$, and compute $\frac{\partial L}{\partial m}$. Now we know how Loss changes if only $m$ moves.

Imagine adjusting a TV: one knob controls brightness, another controls volume. Changing brightness doesn't directly rotate the volume knob, and vice versa. Partial derivatives work the same way — one parameter moves while everything else is temporarily frozen.

## 5️⃣ Deriving the Gradient for $b$

$$L = \sum (y - mx - b)^2$$

Take the derivative. Power rule first: $2(y - mx - b)$. Then chain rule — the derivative of $y - mx - b$ with respect to $b$ is $-1$. Multiply:

$$\frac{\partial L}{\partial b} = -2 \sum (y - mx - b)$$

Exactly what the code computes:

```python
slope_b = -2 * np.sum(y - m * X.ravel() - b)
```

Nothing magical — it's simply the mathematical derivative translated into NumPy.

## 6️⃣ Deriving the Gradient for $m$

Now differentiate with respect to $m$. Power rule again: outer derivative $2(y - mx - b)$. Inner derivative — the derivative of $-mx$ with respect to $m$ is $-x$. Multiply:

$$\frac{\partial L}{\partial m} = -2 \sum (y - mx - b) x$$

Code becomes:

```python
slope_m = -2 * np.sum((y - m * X.ravel() - b) * X.ravel())
```

Notice the extra `* X` — this appears because the derivative of $mx$ is $x$.

## 7️⃣ The Gradient Vector

Now we have two derivatives: $\frac{\partial L}{\partial m}$ and $\frac{\partial L}{\partial b}$. Together they form the Gradient:

$$\nabla L = \left[\frac{\partial L}{\partial m}, \frac{\partial L}{\partial b}\right]$$

Think of it as a GPS arrow. Instead of saying "move left," it says "move 3 meters east AND 5 meters south at the same time." The Gradient gives one direction that accounts for both parameters together.

## 8️⃣ Why Both Parameters Must Update Simultaneously

This is one concept that confuses almost everyone.

Suppose current parameters are $m = 100$, $b = -120$. From these values you compute the gradient for $m$ and the gradient for $b$. These gradients describe the slope at exactly that point on the loss surface.

Imagine standing on a mountain. You ask, "what is the slope right here?" Someone answers. Then, before taking the first step, you teleport somewhere else — the old slope is no longer valid, because the terrain has changed.

Exactly the same thing happens if you update $b$ first and then compute $m$ using the new $b$ — you've mixed information from two different locations on the loss surface.

Instead, we compute both gradients first:

```python
slope_b = ...
slope_m = ...
```

Then update both parameters together:

```python
b = b - lr * slope_b
m = m - lr * slope_m
```

Only after both updates do we move to the next epoch. This preserves the mathematical meaning of the gradient vector.

## 9️⃣ The Complete Training Loop

Every epoch looks like this:

```
Current m, b
      │
      ▼
Predict ŷ = mx + b
      │
      ▼
Compute Loss
      │
      ▼
Compute ∂L/∂m
Compute ∂L/∂b
      │
      ▼
Update m and b
      │
      ▼
Repeat
```

This loop continues until the parameters stop changing significantly.

## 🥣 Why the Loss Surface Looks Like a Bowl

With one parameter, the loss function formed a parabola. With two parameters, that parabola extends into another dimension. Imagine rotating the curve around its center — you get a bowl.

The bottom of the bowl is the lowest possible loss. Every point on the bowl corresponds to one unique pair $(m, b)$. For example:

- $m = 10$, $b = -20$ → Loss $= 950$
- $m = 25$, $b = -4$ → Loss $= 12$

Every coordinate has its own loss value. Gradient Descent simply walks downhill until it reaches the lowest point.

## 🏔️ The 3D Journey

Suppose we start at $m = 100$, $b = -120$. This point lies high on the wall of the bowl.

Each epoch:
1. Compute gradients
2. Move downhill
3. Compute new gradients
4. Move again

The steps become smaller as the bowl flattens near the bottom because the gradient magnitude naturally decreases.

## 🎯 Why Contour Plots Exist

A 3D plot is beautiful, but it's also difficult to analyze from every angle. Instead, imagine looking directly down at the bowl from above. Each ring represents points with the same loss value.

- Center → lowest loss
- Outer rings → higher loss

Gradient Descent leaves a trail of dots moving toward the center. The spacing between the dots tells you how large each update was. Large gaps early on indicate big steps on the steep part of the surface, while tightly packed dots near the center show the optimizer slowing down as it converges.

## 👀 Watching Each Parameter Learn

You can also plot each parameter separately.

**$m$ vs Epochs:** $100 \rightarrow 80 \rightarrow 50 \rightarrow 30 \rightarrow 27.3 \rightarrow 27.2 \rightarrow 27.2 \rightarrow 27.2$ — plateau. The slope has converged.

**$b$ vs Epochs:** $-120 \rightarrow -70 \rightarrow -30 \rightarrow -8 \rightarrow -3.5 \rightarrow -3.5 \rightarrow -3.5$ — plateau. The intercept has converged.

**Cost vs Epochs:** $9000 \rightarrow 4000 \rightarrow 900 \rightarrow 100 \rightarrow 20 \rightarrow 12 \rightarrow 12 \rightarrow 12$ — plateau. The model has learned as much as it can.

## 🧠 The Biggest Takeaway

Optimizing only $b$ teaches the mechanics of Gradient Descent, but optimizing both $m$ and $b$ reveals its true nature. The optimizer is no longer moving along a one-dimensional curve; it is navigating a two-dimensional parameter space guided by a gradient vector, where each partial derivative measures how the loss changes with respect to one parameter while temporarily holding the others fixed. By computing all gradients at the current point, updating every parameter simultaneously, and repeating this process, Gradient Descent steadily descends the bowl-shaped loss surface until both the slope and intercept settle into their optimal values. This same idea extends beyond two parameters to models with millions or even billions of weights, which is why the underlying optimization principle scales from simple linear regression all the way to modern deep learning.
