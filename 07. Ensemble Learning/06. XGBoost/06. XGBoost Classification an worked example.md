# 🦾 The Student Who Walked Through Every Suit: XGBoost Classification, Worked by Hand With Two Features

> *"A new student is never judged by the last tree alone. They walk through every tree in order, each one adds a small correction to their score, and only at the very end does that score become a probability."*

The earlier classification chapter showed the machinery on one feature (CGPA). This chapter does what that one could not: **two features, two boosting trees, one training student followed through the machine, and one completely new student sent through the finished model.**

Two questions you asked earlier will be answered on the way:

> 💭 *"How does XGBoost decide whether to split on CGPA or on IQ?"*
> 💭 *"Does the final prediction pass through all the models?"*

> ⚠️ **Scope.** This follows the simplified lecture formulation: log-odds → probability → residuals → Similarity Score → Gain → leaf output → learning-rate update, with $\lambda = 0$ and **one split per tree**. Every number below was recomputed (and cross-checked with real XGBoost), not copied. The notes at the end list the corrections to the source.

## 📋 The Dataset

| Student | CGPA | IQ | Placement |
|---------|-----:|---:|----------:|
| A | 5.70 | 70 | 0 |
| B | 6.25 | 110 | 1 |
| C | 7.10 | 90 | 0 |
| D | 8.15 | 120 | 1 |
| E | 9.60 | 80 | 1 |
| F | 8.80 | 100 | 0 |

$$y = [0, 1, 0, 1, 1, 0]$$

Three positives, three negatives.

**Goal:** given CGPA and IQ, predict whether a *new* student gets placed. The student we will eventually test: **CGPA = 8.5, IQ = 95**.

---

## 🧱 A First Misunderstanding to Clear

XGBoost does **not** do this:

```
Student A → train a model
Student B → train a model
Student C → train a model
```

The **whole dataset trains each tree**. We only *pick* one student at a time to watch how their prediction changes as the model improves.

---

## 1️⃣ Stage One: "I Have No Clue, So 50%"

Three of six students were placed:

$$p = \frac{3}{6} = 0.5$$

Convert to log-odds:

$$F_0 = \ln\!\left(\frac{0.5}{0.5}\right) = \ln(1) = \boxed{0}$$

Every student starts with a log-odds of 0, which means a 50% probability for everyone. The most honest prediction there is: *I don't know, therefore 50%.*

| CGPA | IQ | Initial log-odds |
|-----:|---:|----:|
| 5.70 | 70 | 0 |
| 6.25 | 110 | 0 |
| 7.10 | 90 | 0 |
| 8.15 | 120 | 0 |
| 9.60 | 80 | 0 |
| 8.80 | 100 | 0 |

### 📏 The first residuals

$$p = \frac{e^{F}}{1 + e^{F}} = \frac{e^0}{1 + e^0} = 0.5 \qquad r = y - p$$

| Student | Actual | Prediction | Residual |
|---------|-------:|-----------:|---------:|
| A | 0 | 0.5 | −0.5 |
| B | 1 | 0.5 | +0.5 |
| C | 0 | 0.5 | −0.5 |
| D | 1 | 0.5 | +0.5 |
| E | 1 | 0.5 | +0.5 |
| F | 0 | 0.5 | −0.5 |

The next tree's job is to **learn these residuals**, not the placements.

## 2️⃣ Both Features Compete

> 💭 *"Which split, using either CGPA or IQ, creates groups with the most useful correction signal?"*

This is where XGBoost differs from an ordinary classification tree: it judges each candidate by the **Similarity Score and Gain**.

The Similarity Score for classification:

$$SS = \frac{\left(\sum r_i\right)^2}{\sum p_i(1-p_i) + \lambda}, \qquad \lambda = 0$$

Right now every $p = 0.5$, so every sample has $p(1-p) = 0.25$. The root's residuals sum to $0$, so $SS_{\text{root}} = 0$.

### 🔎 A closer look at the IQ split the source highlights

Sorted by IQ (the source's own table listed Student E out of order, so here it is in true IQ order):

| Student | IQ | Residual |
|---------|---:|---------:|
| A | 70 | −0.5 |
| E | 80 | +0.5 |
| C | 90 | −0.5 |
| F | 100 | −0.5 |
| B | 110 | +0.5 |
| D | 120 | +0.5 |

Try $\text{IQ} < 105$:

```
IQ < 105 (LEFT)        IQ ≥ 105 (RIGHT)
A  −0.5                B  +0.5
C  −0.5                D  +0.5
E  +0.5
F  −0.5
```

- **Left:** sum $= -0.5 - 0.5 + 0.5 - 0.5 = -1$; Hessian $= 4 \times 0.25 = 1$; $SS_L = \dfrac{1}{1} = \boxed{1}$
- **Right:** sum $= +1$; Hessian $= 2 \times 0.25 = 0.5$; $SS_R = \dfrac{1}{0.5} = \boxed{2}$

$$\text{Gain} = SS_L + SS_R - SS_{\text{root}} = 1 + 2 - 0 = \boxed{3}$$

The right leaf is perfect: two corrections, both $+0.5$, pointing the same way.

### 📊 But XGBoost tries **everything**

The source says "the best CGPA split gives a lower gain than the best IQ split" without showing it. Here is the whole search, for both features:

| Split | Left | Right | $SS_L$ | $SS_R$ | Gain |
|---|---|---|---:|---:|---:|
| CGPA < 5.975 | A | B C D E F | 1.0000 | 0.2000 | 1.2000 |
| CGPA < 6.675 | A B | C D E F | 0.0000 | 0.0000 | 0.0000 |
| CGPA < 7.625 | A B C | D E F | 0.3333 | 0.3333 | 0.6667 |
| CGPA < 8.475 | A B C D | E F | 0.0000 | 0.0000 | 0.0000 |
| CGPA < 9.200 | A B C D F | E | 0.2000 | 1.0000 | 1.2000 |
| IQ < 75 | A | B C D E F | 1.0000 | 0.2000 | 1.2000 |
| IQ < 85 | A E | B C D F | 0.0000 | 0.0000 | 0.0000 |
| IQ < 95 | A C E | B D F | 0.3333 | 0.3333 | 0.6667 |
| **IQ < 105** | A C E F | B D | 1.0000 | 2.0000 | **3.0000** |
| IQ < 115 | A B C E F | D | 0.2000 | 1.0000 | 1.2000 |

The best CGPA split reaches only 1.2. IQ < 105 reaches 3.

> 💭 *"How does XGBoost decide between CGPA and IQ?"*

It doesn't feel that "IQ seems important today". It tries **every candidate threshold of every feature**, computes the Gain of each, and keeps the highest. Here that is $\text{IQ} < 105$. The features compete on the same scoreboard.

$$\boxed{\text{Tree 1 root: IQ} < 105}$$

---

## 3️⃣ Tree 1 and Its Leaf Outputs

$$\text{Output} = \frac{\sum r_i}{\sum p_i(1-p_i) + \lambda}$$

- **Left:** $\dfrac{-1}{4 \times 0.25} = \boxed{-1}$
- **Right:** $\dfrac{+1}{2 \times 0.25} = \boxed{+2}$

```
             IQ < 105 ?
             /        \
           YES         NO
            ↓           ↓
          −1.0         +2.0
```

These are corrections in **log-odds space**, not probabilities.

---

## 4️⃣ Adding Tree 1, Gently

Use the learning rate $\eta = 0.3$:

$$F_1(x) = F_0(x) + \eta\, T_1(x)$$

### 👩‍🎓 Watching Student D (CGPA 8.15, IQ 120, actual = 1)

$120 < 105$? No → right leaf → output $+2$:

$$F_1 = 0 + 0.3(2) = \boxed{0.6} \qquad p = \frac{e^{0.6}}{1 + e^{0.6}} \approx \boxed{0.646}$$

```
D:  50%  →  64.6%
```

D had a positive correction, so the model moved up.

### 👨‍🎓 Watching Student A (CGPA 5.70, IQ 70, actual = 0)

$70 < 105$? Yes → left leaf → output $-1$:

$$F_1 = 0 + 0.3(-1) = \boxed{-0.3} \qquad p = \frac{e^{-0.3}}{1 + e^{-0.3}} \approx \boxed{0.426}$$

```
A:  50%  →  42.6%
```

### 📉 New residuals for everyone

| Student | Actual | New probability | New residual |
|---------|-------:|----------------:|-------------:|
| A | 0 | 0.426 | −0.426 |
| B | 1 | 0.646 | +0.354 |
| C | 0 | 0.426 | −0.426 |
| D | 1 | 0.646 | +0.354 |
| E | 1 | 0.426 | **+0.574** |
| F | 0 | 0.426 | −0.426 |

Student E stands out: actual placement is 1 but the model says only 0.426, so E still needs a large positive correction. **Tree 1 had no way to see E**, because E's IQ (80) put E on the same side as the students who were not placed. Tree 2 will have to deal with that.

---

## 5️⃣ Tree 2: A Different Feature Takes Over

Residuals changed, so the **Hessians changed too**. They are no longer all 0.25:

- $p = 0.426$ → $p(1-p) = 0.2445$ (students A, C, E, F)
- $p = 0.646$ → $p(1-p) = 0.2288$ (students B, D)

The search runs again, over both features, on the new residuals:

| Split | Left | Right | $SS_L$ | $SS_R$ | Gain |
|---|---|---|---:|---:|---:|
| CGPA < 5.975 | A | B C D E F | 0.7408 | 0.1567 | 0.8975 |
| CGPA < 6.675 | A B | C D E F | 0.0107 | 0.0063 | 0.0170 |
| CGPA < 7.625 | A B C | D E F | 0.3439 | 0.3528 | 0.6967 |
| CGPA < 8.475 | A B C D | E F | 0.0214 | 0.0453 | 0.0667 |
| **CGPA < 9.200** | A B C D F | E | 0.2709 | 1.3499 | **1.6207** |
| IQ < 75 | A | B C D E F | 0.7408 | 0.1567 | 0.8975 |
| IQ < 85 | A E | B C D F | 0.0453 | 0.0214 | 0.0667 |
| IQ < 95 | A C E | B D F | 0.1044 | 0.1142 | 0.2185 |
| IQ < 105 | A C E F | B D | 0.5043 | 1.0976 | 1.6019 |
| IQ < 115 | A B C E F | D | 0.1003 | 0.5488 | 0.6491 |

**Winner: CGPA < 9.2**, with Gain 1.6207.

> ⚠️ **Look at how narrow that win is.** $\text{IQ} < 105$, the very split Tree 1 used, scores **1.6019**, only about 0.02 behind. The source presents Tree 2's choice of CGPA as a clear discovery ("this is exactly why we wanted two features"). The mechanism is real (each tree re-searches *all* features against the *current* residuals), but on this tiny dataset the choice is close to a toss-up. A slight change in the data could flip it.

Leaf outputs for CGPA < 9.2:

- **Left** (A, B, C, D, F): $\approx \boxed{-0.477}$
- **Right** (E alone): $\approx \boxed{+2.350}$

```
              CGPA < 9.2 ?
              /          \
            YES           NO
             ↓             ↓
          −0.477         +2.350
```

Tree 2 does exactly what the residual table promised: it isolates E, the student Tree 1 left behind, and hands E a big positive correction.

### 🔑 Two trees, two different features

```
Tree 1 → IQ        Tree 2 → CGPA
```

Each tree is free to use whichever feature best reduces the **remaining** error. No tree is obliged to reuse its predecessor's feature.

## 6️⃣ A New Student Arrives 🎯

$$\boxed{\text{CGPA} = 8.5, \quad \text{IQ} = 95}$$

This student was never in the training data. We do not know their placement; that is why we have a model.

### Through Tree 1

$95 < 105$? Yes → left leaf → $T_1 = -1$.

$$F_1 = 0 + 0.3(-1) = \boxed{-0.3} \qquad p_1 = \frac{e^{-0.3}}{1+e^{-0.3}} \approx \boxed{42.6\%}$$

But we are not finished.

### Through Tree 2

$8.5 < 9.2$? Yes → left leaf → $T_2 = -0.477$.

$$F_2 = F_1 + \eta\, T_2 = -0.3 + 0.3(-0.477) = -0.3 - 0.1431 \approx \boxed{-0.443}$$

### Convert and decide

$$p = \frac{e^{-0.443}}{1 + e^{-0.443}} \approx \boxed{39.1\%} \quad \Rightarrow \quad 0.391 < 0.5 \quad \Rightarrow \quad \boxed{\text{Class 0: not placed}}$$

### The whole journey in one picture

```
             NEW STUDENT (8.5, 95)
                      │
                BASE MODEL F = 0
                  (50%)
                      │
           Tree 1: IQ < 105 ?  → YES
                      │
              correction −1.0 × 0.3
                      │
                 F = −0.3  (42.6%)
                      │
           Tree 2: CGPA < 9.2 ?  → YES
                      │
              correction −0.477 × 0.3
                      │
                 F = −0.443  (39.1%)
                      │
              39.1% < 50%  →  class 0
```

## 🔁 "Does the Final Prediction Pass Through All the Models?"

> 💭 *"Does the final prediction pass through all the models?"*

**Yes.** And it is not a vote.

```
Not this (voting):                This (additive):
Tree 1 says 0                     Base prediction
Tree 2 says 1                          +
Tree 3 says 0                     Tree 1 correction
majority = 0                           +
                                  Tree 2 correction
                                       +
                                  Tree 3 correction …
                                       =
                                  Final log-odds → probability
```

### 🆚 Versus Random Forest

```
Random Forest                       XGBoost
Tree 1 → 1                          Base model
Tree 2 → 0                              ↓
Tree 3 → 1                          Tree 1 fixes some errors
Tree 4 → 1                              ↓
Tree 5 → 0                          Tree 2 fixes remaining errors
Majority → 1                            ↓
                                    Tree 3 fixes what is left …
```

- **Random Forest = many independent opinions.**
- **XGBoost = a sequence of corrections.**

The final model is not one tree that asks "CGPA? then IQ?". It is:

```
              XGBoost
                 │
       ┌─────────┴─────────┐
    Tree 1              Tree 2
      IQ                 CGPA
  Correction 1       Correction 2
       └─────────┬─────────┘
          Add the corrections
                 ↓
        Final probability
```

$$\boxed{F(x) = F_0 + \eta T_1(x) + \eta T_2(x) + \eta T_3(x) + \cdots} \qquad \boxed{P(y=1 \mid x) = \frac{1}{1 + e^{-F(x)}}}$$

---

## 🧰 The Mark-Suit Picture

```
Mark 1:  "I'll make a rough prediction."
Mark 2:  "I'll fix what Mark 1 got wrong."
Mark 3:  "I'll fix what Mark 1 + Mark 2 still got wrong."
Mark 4:  "Still some errors? Hand them over."
```

A new student does not get evaluated by just the last suit. They go through **every suit in sequence**, each adding its correction.

> **The one sentence to remember:** *Start with a probability, convert it to log-odds, calculate the errors, build a tree that predicts a useful correction using any feature, add a small part of that correction, recalculate the errors, and keep doing it.*

## 🔭 What a Third Tree Would Do

The source stops at two trees. Running real XGBoost for a third round on the same data (with the settings listed in the fact-check below) shows the story continuing:

| | After 2 trees | After 3 trees |
|---|---:|---:|
| New student (8.5, 95) | 39.1% | 33.5% |
| Student E (actual = 1) | 60.0% | 54.0% |

Tree 3 returns to $\text{IQ} < 105$ (gain 1.89). Features take turns as the residuals change shape. And the new student's probability keeps drifting *further below* 50%. Whether that is a good prediction or an overconfident one on six training rows is a question the model cannot answer for itself; a real model would be checked on held-out data.

---

## 🛠️ A Practical Warning: Defaults Can Refuse to Split

With **default** settings, real XGBoost builds **no split at all** on this dataset; the tree is a single leaf. The default `min_child_weight` is 1, compared against the **sum of Hessians in each child**. Here the right child has $2 \times 0.25 = 0.5$, below 1, so the split is rejected. Setting `min_child_weight=0` reproduces this chapter exactly.

On six rows, almost any real-world safeguard will interfere. That is not XGBoost being wrong; it is XGBoost being protective.

---

## 🌉 ML Bridge

- **Each tree is a fresh competition.** Every round, every feature's every threshold is scored against the *current* residuals. Feature importance in real XGBoost models comes from many such rounds.
- **Residuals show what is still unexplained.** Student E's large residual after Tree 1 is exactly the signal that made a *new* split worthwhile.
- **Hessians move as predictions move.** Round one had a flat 0.25 per sample; round two did not. A sample the model is already sure about contributes little.
- **Probability is a view, not the workspace.** Corrections add in log-odds; the sigmoid is applied once, at the end.

---

## 🌀 Deepest Realization

> The model never stores "what IQ means" or "what CGPA means". It stores a list of **small questions with small corrections attached**. Prediction is just walking a new student through that list and adding up what each question says, then asking the sigmoid what the total looks like as a probability.

---

## ✅ Final Takeaway

> *"Two features, two trees, six students, one new arrival: each tree asks the question that best fixes what is still wrong, adds only a fraction of its answer, and the new student collects every correction in order before the sigmoid turns the total into a verdict."*
