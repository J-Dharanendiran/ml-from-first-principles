# 🎚️ Hard Votes, Soft Votes, and Giving the Experts Different Weights: The Voting Classifier

> *"Hard voting asks who won. Soft voting asks how sure everyone was."* 🎯

In the last chapter you proved, with arithmetic, that three 70% models can reach 78.4% if their mistakes don't line up. That was the *why*. Now the lecture opens the toolbox and shows the machinery: **Hard Voting, Soft Voting, weights, tuning, and the actual `VotingClassifier` in `scikit-learn`.**

---

## 🧑‍🔬 Meet the Experts

> 🤔 *"What exactly is a Voting Classifier, and what are the 'base estimators' everyone keeps mentioning?"*

A **Voting Classifier** is an ensemble that trains **multiple classification models** and combines their predictions into one final prediction.

```text
Dataset
   │
   ├── Logistic Regression
   ├── SVM
   └── Random Forest
```

These individual models are the **base estimators** (also called base models). Think of them as experts sitting on a panel:

```text
Voting Classifier
       │
       ├── Expert 1 → Logistic Regression
       ├── Expert 2 → SVM
       └── Expert 3 → Random Forest
```

Each expert learns independently. The ensemble itself doesn't invent a brand-new algorithm; it **coordinates the predictions** of these experts.

A new sample arrives:

```text
                New sample
                    │
        ┌───────────┼───────────┐
        ↓           ↓           ↓
   Logistic       SVM       Random Forest
        ↓           ↓           ↓
      Class 0     Class 1     Class 0
        │           │           │
        └───────────┼───────────┘
                    ↓
               Voting
                    ↓
                 Class 0
```

> 🤔 *"Why these three? Why not three copies of the same algorithm?"*

Because these three learn in different ways:

| Expert | How it sees the world |
|---|---|
| **Logistic Regression** | Draws a decision boundary from a linear relationship in feature space |
| **SVM** | Looks for the boundary that maximizes the margin |
| **Random Forest** | Combines many decision trees and can capture nonlinear relationships |

Different ways of learning means they may make **different mistakes**, and different mistakes are exactly what an ensemble feeds on. (The point isn't that these three are *the* right combination. The point is that different algorithms can share one ensemble.)

## 🧱 Hard Voting: Only the Final Answer Counts

The first type of voting is the one you already know.

```text
Model 1 → Class 0
Model 2 → Class 0
Model 3 → Class 1

Class 0 → 2 votes
Class 1 → 1 vote
```

$$
\boxed{\text{Class 0}}
$$

**Hard voting only looks at the final predicted class.** The confidence behind each prediction is thrown away.

> 🤔 *"Wait. Throws away the confidence? Is that a problem?"*

Look at this panel:

```text
Model 1 → Class A with 51% confidence
Model 2 → Class A with 51% confidence
Model 3 → Class B with 99% confidence
```

Hard voting sees only `A, A, B`, so **A wins 2 to 1**. It never notices that Model 3 was practically shouting.

That blind spot is why soft voting exists.

---

## 🌊 Soft Voting: Listening to How Sure Each Expert Is

**Soft voting uses the predicted probabilities** from the models, not just their final classes.

Two classes, three models:

```text
Model 1:  P(Class 0) = 0.80   P(Class 1) = 0.20
Model 2:  P(Class 0) = 0.60   P(Class 1) = 0.40
Model 3:  P(Class 0) = 0.30   P(Class 1) = 0.70
```

Average each class:

$$
P(\text{Class 0}) = \frac{0.80 + 0.60 + 0.30}{3} = \frac{1.70}{3} \approx 0.567
$$

$$
P(\text{Class 1}) = \frac{0.20 + 0.40 + 0.70}{3} = \frac{1.30}{3} \approx 0.433
$$

```text
Class 0 → 56.7%
Class 1 → 43.3%
```

$$
\boxed{\text{Class 0}}
$$

### ✅ Sanity Check

0.567 + 0.433 = 1.000, so the averaged probabilities still sum to 1. ✔️

### ⚔️ Hard vs Soft, side by side

| | **Hard Voting** | **Soft Voting** |
|---|---|---|
| Uses | Predicted class | Predicted probability |
| Model output | `0`, `1`, etc. | `[P(0), P(1), ...]` |
| Combination | Majority vote | Average probabilities |
| Confidence considered? | ❌ No | ✅ Yes |
| Scikit-learn setting | `voting="hard"` | `voting="soft"` |

$$
\text{Hard} = \text{most common predicted class} \qquad \text{Soft} = \text{class with the highest average probability}
$$

## 🔍 The Case Where Soft Voting Flips the Answer

> 🤔 *"Can the two methods actually disagree?"*

Yes. Reuse the panel from before, with the full probabilities:

```text
Model 1:  A = 0.51   B = 0.49
Model 2:  A = 0.51   B = 0.49
Model 3:  A = 0.01   B = 0.99
```

**Hard voting:** `A, A, B` → **A** wins.

**Soft voting:**

$$
P(A) = \frac{0.51 + 0.51 + 0.01}{3} = \frac{1.03}{3} \approx 0.343
$$

$$
P(B) = \frac{0.49 + 0.49 + 0.99}{3} = \frac{1.97}{3} \approx 0.657
$$

$$
\boxed{B}
$$

> **Soft voting takes the strength of each model's belief into account.**

Two models were barely leaning toward A; one was nearly certain about B. Soft voting listened to the certainty.

## 🎨 Soft Voting with More Than Two Classes

Soft voting isn't limited to binary problems. Five classifiers, three classes:

```text
Model 1 → [0.20, 0.50, 0.30]
Model 2 → [0.30, 0.40, 0.30]
Model 3 → [0.10, 0.60, 0.30]
Model 4 → [0.20, 0.45, 0.35]
Model 5 → [0.25, 0.50, 0.25]
```

Average **each column**:

$$
P(\text{Class}_k) = \frac{P_1(\text{Class}_k) + P_2(\text{Class}_k) + \dots + P_5(\text{Class}_k)}{5}
$$

| Class | Column sum | ÷ 5 |
|---|---|---|
| Class 1 | 0.20 + 0.30 + 0.10 + 0.20 + 0.25 = 1.05 | **0.21** |
| Class 2 | 0.50 + 0.40 + 0.60 + 0.45 + 0.50 = 2.45 | **0.49** |
| Class 3 | 0.30 + 0.30 + 0.30 + 0.35 + 0.25 = 1.50 | **0.30** |

The largest average wins → **Class 2**.

*(The five probability rows are the lecture's multiclass example structure as reconstructed from the noisy transcript; the column arithmetic is mine and checks out: 0.21 + 0.49 + 0.30 = 1.00.)*

## 🔌 The Fine Print: Soft Voting Needs Probabilities

Soft voting has a practical requirement: each model must be able to output **probabilities**, in `scikit-learn` terms something like `predict_proba()`.

```text
model.predict_proba(X)  →  [[0.2, 0.8]]
                             Class 0 → 20%
                             Class 1 → 80%
```

Some estimators need a setting switched on before they can take part in soft voting. The usual example is `SVC(probability=True)`, which you'll see in the code below.

## 🚨 The Lesson Nobody Wants: Voting Can Make Things Worse

> 🤔 *"So voting always beats my best single model, right?"*

No, and the lecture says so explicitly.

```text
Logistic Regression → 90%
Random Forest       → 88%
SVM                 → 87%
Voting              → 85%   ← worse than every single model
```

Why could that happen?

- models make **correlated errors**
- one model is **substantially weaker** than the others
- probabilities **aren't well calibrated**
- the **dataset is small**
- the chosen **combination isn't suitable**
- the **weights** aren't appropriate

$$
\text{Ensemble} \neq \text{automatic improvement}
$$

More models means more models. It does not mean better predictions by itself.

## ⚖️ Weights: Not Every Expert Deserves an Equal Vote

By default, every model gets the same influence:

```text
Model 1 → weight 1
Model 2 → weight 1
Model 3 → weight 1      (1 : 1 : 1)
```

> 🤔 *"What if one model is clearly better than the others?"*

Say the models score 90%, 80%, and 70%. You might want the 90% model to speak louder. That's what **weights** do. The lecture presents weights as a **hyperparameter** that gives different base models different importance.

### Weighted hard voting

```text
Model 1 → predicts A   (weight 5)
Model 2 → predicts B   (weight 1)
Model 3 → predicts B   (weight 1)
```

Unweighted: `A → 1 vote`, `B → 2 votes` → **B**.

Weighted: `A → 5`, `B → 1 + 1 = 2` → **A** wins. 🏆

The vote is no longer democratic. One model has more voting power.

### Weighted soft voting

Instead of a plain average, use a **weighted average**:

$$
P_{\text{final}} = \frac{w_1 P_1 + w_2 P_2 + w_3 P_3}{w_1 + w_2 + w_3}
$$

Try it on the first soft-voting panel (0.80 / 0.60 / 0.30 for Class 0) with weights **3 : 1 : 1**. *(This numeric example is mine, to make the formula concrete.)*

$$
P(\text{Class 0}) = \frac{3(0.80) + 1(0.60) + 1(0.30)}{5} = \frac{3.30}{5} = 0.66
$$

$$
P(\text{Class 1}) = \frac{3(0.20) + 1(0.40) + 1(0.70)}{5} = \frac{1.70}{5} = 0.34
$$

Class 0 rose from 56.7% to 66% because Model 1 (the one most sure about Class 0) now speaks three times as loudly. And 0.66 + 0.34 = 1. ✔️

---

## 🔧 Weights Are a Hyperparameter, So Tune Them

A **hyperparameter** is a setting you choose before or around training, not something the model learns as an ordinary parameter. In `VotingClassifier`:

```python
weights=[1, 1, 1]
```

You could try `[2, 1, 1]`, `[3, 1, 1]`, `[5, 2, 1]`, and so on. The lecture demonstrates changing weights and watching accuracy move.

> 🤔 *"Am I supposed to keep guessing weights by hand forever?"*

No. Use a search procedure, the same idea as `GridSearchCV`, which you've already met:

```python
param_grid = {
    "weights": [
        [1, 1, 1],
        [2, 1, 1],
        [3, 1, 1],
        [1, 2, 1],
        [1, 1, 2]
    ]
}
```

Evaluate each configuration with **cross-validation**, then keep the best one.

## 🔁 A Second Way to Build the Crowd: Same Algorithm, Different Settings

You don't have to use different algorithms at all. The lecture also builds a voting ensemble from **many versions of one algorithm**:

```text
SVM degree=1
SVM degree=2
SVM degree=3
SVM degree=4
SVM degree=5
```

> 🤔 *"How can five SVMs be 'different' if it's the same algorithm?"*

Because a hyperparameter changes the *hypothesis* the model learns. `degree=1` and `degree=5` can create very different decision boundaries:

```text
Same algorithm
      ↓
Different hyperparameters
      ↓
Different learned models
      ↓
Potentially different errors
      ↓
Useful ensemble diversity
```

Instead of asking *"which degree is best?"*, you let them all vote.

```text
                 Dataset
                    │
        ┌───────────┼───────────┐
        ↓           ↓           ↓
     SVM d=1     SVM d=2     SVM d=3 ...
        │           │           │
        └───────────┼───────────┘
                    ↓
                  Voting
```

So the lecture gives you **two construction strategies**:

| Strategy | Example |
|---|---|
| **Different algorithms** | Logistic Regression + SVM + Random Forest |
| **Same algorithm, different hyperparameters** | SVM(d=1), SVM(d=2), SVM(d=3), ... |

Both are valid. Both trace back to the same principle from the previous chapters: **diversity of errors matters.**

## 💻 The Machinery: `VotingClassifier` in Code

### The structure

```python
from sklearn.ensemble import VotingClassifier

voting_clf = VotingClassifier(
    estimators=[
        ("lr",  logistic_regression),
        ("svm", svm_model),
        ("rf",  random_forest)
    ],
    voting="hard"          # or "soft"
)
```

`estimators` is simply a list of `(name, model)` pairs. In `("lr", lr)`, `"lr"` is the identifier and `lr` is the model.

With weights:

```python
voting_clf = VotingClassifier(
    estimators=[("lr", lr), ("svm", svm), ("rf", rf)],
    voting="soft",
    weights=[3, 2, 1]
)
```

### The whole workflow, step by step

**Step 1: Prepare data**

```python
X_train, X_test, y_train, y_test
```

**Step 2: Define the base models**

```python
lr  = LogisticRegression()
svm = SVC(probability=True)   # probabilities needed for soft voting
rf  = RandomForestClassifier()
```

**Step 3: Wrap them in a VotingClassifier**

```python
voting = VotingClassifier(
    estimators=[("lr", lr), ("svm", svm), ("rf", rf)],
    voting="soft"
)
```

**Step 4: Train**

```python
voting.fit(X_train, y_train)
```

**Step 5: Predict**

```python
y_pred = voting.predict(X_test)
```

**Step 6: Evaluate**

```python
accuracy_score(y_test, y_pred)
```

### What happens inside `fit` and `predict`

```text
fit(X_train, y_train)
   X_train ─┬──→ Logistic Regression
            ├──→ SVM
            └──→ Random Forest        (each estimator gets trained)
```

```text
predict(X_test)

HARD:  Model 1 → class ┐
       Model 2 → class ├→ Majority → final class
       Model 3 → class ┘

SOFT:  Model 1 → probabilities ┐
       Model 2 → probabilities ├→ Average / weighted average → highest class
       Model 3 → probabilities ┘
```

## 🔬 Experiment, Don't Assume

The lecture stresses **experimentation** because there is no universal rule such as "always use soft voting" or "always use three models."

```text
Try different models
       ↓
Try hard voting
       ↓
Try soft voting
       ↓
Try weights
       ↓
Try different hyperparameters
       ↓
Evaluate properly
       ↓
Choose based on validation performance
```

### 🚫 One big caution: don't celebrate training accuracy

```text
Model A → 99% training accuracy
Model B → 98% training accuracy
Voting  → 99.5% training accuracy   ← this alone proves nothing
```

You care about **generalization**, so evaluate with validation data, cross-validation, or proper test data. The lecture also notes that the dataset in its demo is small, so its metric shouldn't be treated as universally reliable.

```text
       └───────────────┘                │ ...            │
              │                          └────────────────┘
              └──────────────┬────────────────────┘
                             ↓
                       VotingClassifier
                             │
                    ┌────────┴────────┐
                    ↓                 ↓
                 HARD              SOFT
                 VOTING            VOTING
                    │                 │
             Class predictions   Probabilities
                    │                 │
                    ↓                 ↓
               Majority          Average /
                                  weighted average
                    │                 │
                    └────────┬────────┘
                             ↓
                     Final prediction
```

### The formulas to keep in your notes

**Hard voting**

$$
\text{Final class} = \text{majority vote}
$$

**Soft voting** (M models, class $k$)

$$
P_k = \frac{1}{M} \sum_{i=1}^{M} P_{ik}
$$

**Weighted voting**

$$
P_k = \frac{\sum_i w_i P_{ik}}{\sum_i w_i}
$$

### The vocabulary

- **Base estimators**: the individual models inside the ensemble
- **Diversity**: models or configurations should ideally make different errors
- **Hyperparameter**: `weights` is one; so is the SVM `degree`
- **Critical warning**: voting does **not** guarantee improvement, so validate it

## 🌀 Deepest Realization

> **Hard voting counts hands. Soft voting weighs conviction. Weights decide whose conviction counts more. And none of it helps unless the experts are good and wrong in different places.**

The `VotingClassifier` syntax is only machinery. The **why** (good models, diverse errors, sensible aggregation) is what carries over to every ensemble that follows.
