# 🔢 The Number That Refused to Be Zero

> *"I classified this correctly. Why should I change anything?"*
> — the Perceptron, right before that habit became its biggest weakness.

You already know the update rule by heart:

$$
w_{new} = w_{old} + \eta(y - \hat{y})\,x
$$

And you already know the four cases it produces. This chapter sits inside that update and asks one very specific question: **what happens to $y-\hat{y}$ when the output mechanism itself changes?**

---

## 1. The four cases, one more time — but slower

With the step function, $\hat{y}$ can only ever be $0$ or $1$. That gives exactly four combinations with $y$:

| Actual $y$ | Prediction $\hat{y}$ | $y-\hat{y}$ | Update |
|---|---|---|---|
| 1 | 1 | 0 | No change |
| 0 | 0 | 0 | No change |
| 1 | 0 | +1 | Positive update |
| 0 | 1 | -1 | Negative update |

*Why does it feel wrong that the first two rows just... do nothing?*

Because "correctly classified" and "confidently, meaningfully classified" are not the same claim — and the step function can't tell you which one you're looking at.

---

## 2. Watch the zero happen, case by case

**Case 1 — $y=1$, $\hat{y}=1$:**
$$y - \hat{y} = 1 - 1 = 0 \quad\Rightarrow\quad w_{new} = w_{old} + \eta(0)x = w_{old}$$

**Case 2 — $y=0$, $\hat{y}=0$:**
$$y - \hat{y} = 0 - 0 = 0 \quad\Rightarrow\quad w_{new} = w_{old}$$

Both correctly classified. Both produce **zero movement**. The Perceptron's reasoning is consistent, at least:

> "I classified this correctly. Why should I change anything?"

Reasonable — until you notice what it's throwing away to get there.

**Case 3 — $y=1$, $\hat{y}=0$ (a miss):**
$$y-\hat{y}=1 \quad\Rightarrow\quad w_{new}=w_{old}+\eta x$$
The weights grow in the direction of $x$ — the boundary moves toward this point.

**Case 4 — $y=0$, $\hat{y}=1$ (a miss):**
$$y-\hat{y}=-1 \quad\Rightarrow\quad w_{new}=w_{old}-\eta x$$
The weights move the opposite way.

---

## 3. Where the step function actually loses information

The model's linear score is:

$$
z = w_1x_1 + w_2x_2 + b
$$

for, say, $x_1 = \text{CGPA}$ and $x_2 = \text{IQ}$. The step function collapses it:

$$
\hat{y} = \begin{cases} 1 & z \ge 0 \\ 0 & z < 0 \end{cases}
$$

*But is a $z$ of $0.1$ really the same situation as a $z$ of $100$?*

The step function says yes — both round to $\hat{y}=1$. Humanity built a function that looks at "barely on the right side" and "unmistakably on the right side" and shrugs: **"same thing."** A remarkably aggressive compression algorithm, applied to information you actually needed.

---

## 4. The fix: stop asking a yes/no question

The instructor's move is deceptively simple — keep the same linear score $z$, but replace the step function with the **sigmoid**:

$$
\sigma(z) = \frac{1}{1+e^{-z}}
$$

Instead of snapping to $\{0,1\}$, the output becomes a continuous number between them:

| $z$ | $\sigma(z)$ |
|---|---|
| -5 | ≈ 0.0067 |
| -2 | ≈ 0.119 |
| -1 | ≈ 0.269 |
| 0 | 0.5 |
| 1 | ≈ 0.731 |
| 2 | ≈ 0.881 |
| 5 | ≈ 0.993 |

The model no longer just says *"placement."* It says *"I'm estimating 88.1%."*

---

## 5. A worked example: four points, four honest opinions

Set up a small dataset — two positive points, two negative points, each with a $z$ value already computed. Say the sigmoid outputs come out to roughly:

| Point | Actual $y$ | $z$ | $\hat{y}=\sigma(z)$ |
|---|---|---|---|
| 1 | 1 | positive | 0.80 |
| 2 | 1 | positive | 0.65 |
| 3 | 0 | negative | 0.30 |
| 4 | 0 | negative | 0.15 |

Now compute $y - \hat{y}$ for each:

$$
1-0.80=0.20 \qquad 1-0.65=0.35 \qquad 0-0.30=-0.30 \qquad 0-0.15=-0.15
$$

$$
y-\hat{y} = [\,0.20,\ 0.35,\ -0.30,\ -0.15\,]
$$

**None of these are zero.** That's the entire demonstration, compressed into one line. Under the step function, if these same four points were classified correctly, every one of those differences would have collapsed to $0$, and $\Delta w$ would have vanished four times over. Under sigmoid, every single point still has something to say.

*So does this mean the output can never be exactly zero?*

Strictly: for any finite $z$, $\sigma(z)$ is strictly between $0$ and $1$, so $y-\hat{y}$ is nonzero for finite $z$ — it can shrink toward zero as the model gets more confident, but it never quite lands there. That's a more careful statement than "the difference will never be zero," but the practical effect is the same: **the learning signal survives.**

---

## 6. Reading the four points as forces

Look at the pattern that falls out of the table:

| Actual $y$ | Prediction $\hat{y}$ | $y-\hat{y}$ | Effect |
|---|---|---|---|
| 1 | 0.80 | +0.20 | Push |
| 1 | 0.65 | +0.35 | Push harder |
| 0 | 0.30 | -0.30 | Pull |
| 0 | 0.15 | -0.15 | Pull |

Point 2, correctly classified at $\hat{y}=0.65$, produces a **bigger** update than Point 1, correctly classified at $\hat{y}=0.80$. Not because it's more wrong — it isn't wrong at all — but because the model is *less confident* about it. That's the sentence worth sitting with:

> **"I think this is class 1, but my score is only 0.8."** Even a correct point keeps talking, as long as it isn't perfectly sure of itself.

---

## 🧠 Sanity Check

Watch what happens to the update as confidence climbs. If $\hat{y}=0.55$ for a true positive, the correction is $1-0.55=0.45$ — large. If $\hat{y}=0.98$, the correction shrinks to $1-0.98=0.02$ — tiny. So: **less confident correct prediction ⇒ larger correction; more confident correct prediction ⇒ smaller correction.** That asymmetry is exactly what the step function was incapable of expressing, because it only ever answered "right or wrong," never "how sure."

And one more detail worth being precise about: the video's shorthand — *"the magnitude depends on the distance from the line"* — is intuition, not identity. The sigmoid is a function of $z=w^Tx+b$ directly, while the true geometric signed distance is $\dfrac{w^Tx+b}{\|w\|}$. They move together, but they are not literally the same quantity — $z$ gets scaled by $\|w\|$ before it becomes a real distance.

---

## 🌉 ML Bridge

This is the moment the Perceptron quietly turns into something else. The update everyone in this transcript keeps writing,

$$
w_{new} = w_{old} + \eta(y-\hat{y})x,
$$

*looks* identical in shape to the classic Perceptron rule. But it isn't arrived at the same way anymore. Standard Logistic Regression is trained by minimizing **binary cross-entropy**:

$$
L = -\big[y\log(\hat{p}) + (1-y)\log(1-\hat{p})\big]
$$

Differentiating with respect to $w$ gives:

$$
\nabla_w L = (\hat{p}-y)x
$$

and gradient descent, $w_{new}=w_{old}-\eta\nabla_w L$, becomes:

$$
w_{new}=w_{old}-\eta(\hat{p}-y)x = w_{old}+\eta(y-\hat{p})x
$$

Same final formula — but this time it's derived from an actual loss function being minimized, not hand-waved into place by analogy with the Perceptron. That distinction matters for your Stroke Prediction pipeline: the reason Logistic Regression's probability output is trustworthy isn't just "it uses sigmoid instead of step" — it's that the training objective is explicitly built to reward calibrated confidence, and punish confident wrongness far more than timid wrongness.

There's a second detail worth carrying forward: the update also scales with $x$ itself. Two points with the identical error $y-\hat{y}=0.2$ but feature values $x_1=10$ and $x_1=2$ contribute $0.2(10)=2$ versus $0.2(2)=0.4$ to the weight update. Larger raw feature values exert disproportionate pull — which is exactly why feature scaling isn't cosmetic; it's about making sure every feature gets to vote with the same-sized voice.

| | Perceptron | Logistic Regression |
|---|---|---|
| Linear score | $z=w^Tx+b$ | $z=w^Tx+b$ |
| Activation | Step | Sigmoid |
| Output | 0 or 1 | 0 to 1 |
| Confidence info | ❌ Lost | ✅ Preserved |
| Correct-point update | Usually 0 | Usually nonzero |
| Differentiable | ❌ at threshold | ✅ everywhere |
| Typical loss | Perceptron criterion | Binary cross-entropy |

---

## 🌀 Deepest Realization

The Perceptron asks one blunt question: *"Did I get this right or wrong?"* Correct earns silence. Wrong earns a correction. Logistic Regression asks a richer one: *"How close is my predicted probability to the truth?"* Every point gets to answer — even the ones already on the right side — because being *technically correct* and being *confidently, justifiably correct* were never the same achievement. The step function just never had the vocabulary to tell them apart.

---

## ✅ Final Takeaway

> **"A model that only asks 'right or wrong?' stops listening the moment it hears 'right.' A model that asks 'how sure?' never really stops learning — it just learns more quietly as it gets more confident."**
