# 🚀📈 Gradient Descent From Scratch: Freeing Both Parameters

> *"The moment you stop copying the slope from someone else's answer key, you're not walking a line anymore — you're walking a plane."*

---

Every chapter so far has cheated a little, on purpose. The slope $m$ was always borrowed from sklearn and frozen in place, leaving only the intercept $b$ free to wander down the bowl. That training wheel comes off here. This notebook builds a Linear Regression model completely from scratch — one that learns $m$ *and* $b$ together, with nothing borrowed and nothing assumed.

## Cell 1 — Bringing in the Tools

```python
from sklearn.datasets import make_regression
import matplotlib.pyplot as plt
import numpy as np
from sklearn.model_selection import cross_val_score
```

`make_regression` conjures a synthetic dataset out of thin air — no CSV file required, just a request phrased as code: *"give me data that roughly follows a straight line."* `matplotlib.pyplot` will handle the plotting, and `numpy` carries the real weight — every gradient calculation in this notebook runs through it, since Gradient Descent performs the same arithmetic thousands of times and needs it fast.

> *"What about `cross_val_score`? Is that used anywhere?"*

Interestingly, no. It's imported here but never called in this notebook — a leftover import, the kind that survives in real projects far more often than anyone likes to admit.

## Cell 2 — Generating a Realistic Dataset

```python
X, y = make_regression(n_samples=100, n_features=1, n_informative=1,
                        n_targets=1, noise=20, random_state=13)
```

Each parameter is a decision:

- **`n_samples=100`** — 100 rows, 100 observations.
- **`n_features=1`** — a single input column. One thing being measured, like hours studied, rather than several.
- **`n_informative=1`** — with only one feature to begin with, that feature is naturally the one doing all the work.
- **`n_targets=1`** — a single output, the thing being predicted.
- **`noise=20`** — without noise, every point would sit exactly on a line, which is unrealistic. Noise scatters the points around the line the way real, imperfect measurements do.
- **`random_state=13`** — locks the randomness in place, so the same dataset appears every time this cell runs.

## Cell 3 — Looking Before Learning

```python
plt.scatter(X, y)
```

A scatter plot, nothing more. Every dot is one `(X, y)` pair — before any model has touched the data, this is simply what the relationship looks like on its own.

## Cell 4 & 5 — Holding Some Data Back

```python
from sklearn.model_selection import train_test_split

X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2, random_state=2)
```

> *"Why split the data at all if the goal is just to fit a line?"*

Because fitting a line that matches data it has already *seen* proves very little. `test_size=0.2` reserves 20% of the 100 rows — 20 examples — as data the model will never train on, held back purely to check, afterward, whether what it learned actually generalizes. The remaining 80 rows are what it's allowed to learn from. `random_state=2` just keeps that particular split reproducible.

## Cells 6–9 — Letting sklearn Set the Benchmark

```python
from sklearn.linear_model import LinearRegression

lr = LinearRegression()
```

An empty model — like an empty notebook, nothing has been learned yet.

```python
lr.fit(X_train, y_train)
print(lr.coef_)
print(lr.intercept_)
```

This is where sklearn does its work internally, solving for the best $m$ and $b$. Running it produces something like:

```
[28.126]
-2.271
```

That's the target this notebook's own implementation is chasing: $m \approx 28.13$, $b \approx -2.27$.

```python
y_pred = lr.predict(X_test)

from sklearn.metrics import r2_score
r2_score(y_test, y_pred)
```

`r2_score` measures how well the predictions matched the held-back test data — closer to 1 means a better fit. Here it comes out to roughly **0.63**. That single number is the benchmark every home-built version of this model now has to try to match.

## Cell 10 — Building the Model Yourself ⭐

This is the heart of the notebook: a `GDRegressor` class that reimplements what `LinearRegression()` was doing invisibly, except every step is now visible.

```python
class GDRegressor:

    def __init__(self, learning_rate, epochs):
        self.m = 100
        self.b = -120
        self.lr = learning_rate
        self.epochs = epochs
```

The constructor runs the moment `GDRegressor(...)` is created. `self.m = 100` and `self.b = -120` are not answers — they're starting guesses, deliberately arbitrary, the blindfolded walker's first random position on the hill. `self.lr` stores the learning rate, and `self.epochs` stores how many times the walk will repeat.

```python
    def fit(self, X, y):
        for i in range(self.epochs):
            loss_slope_b = -2 * np.sum(y - self.m*X.ravel() - self.b)
            loss_slope_m = -2 * np.sum((y - self.m*X.ravel() - self.b) * X.ravel())

            self.b = self.b - (self.lr * loss_slope_b)
            self.m = self.m - (self.lr * loss_slope_m)
        print(self.m, self.b)
```

> *"Both gradients look almost identical — what actually separates them?"*

Look closely and the only difference is a trailing `* X.ravel()`.

`X.ravel()` first flattens the input from a column shape like `[[2], [4], [6]]` into a simple 1D array `[2, 4, 6]`, which makes the arithmetic that follows straightforward.

**The gradient with respect to $b$:**

$$\frac{\partial L}{\partial b} = -2 \sum (y_i - mx_i - b)$$

`self.m * X.ravel() + self.b` computes the current predictions $mx + b$. Subtracting those from `y` gives the residuals — how wrong each prediction is. `np.sum(...)` totals them, and the leading `-2` falls directly out of differentiating the squared-error cost function. This gradient answers one question: *"how should the intercept move to reduce the error?"*

**The gradient with respect to $m$:**

$$\frac{\partial L}{\partial m} = -2 \sum \big[(y_i - mx_i - b)\, x_i\big]$$

Same residuals as before — but this time each one is multiplied by its own $x$-value before being summed. That extra multiplication is what makes this the derivative with respect to the *slope* instead of the intercept. It answers a different question: *"how should the line rotate to reduce the error?"*

**Updating both parameters:**

```python
self.b = self.b - (self.lr * loss_slope_b)
self.m = self.m - (self.lr * loss_slope_m)
```

Both follow the same rule — new value equals old value minus the learning rate times the gradient — applied independently to each parameter, in the same iteration. A large gradient moves its parameter further; a small learning rate keeps every move cautious. Together, $m$ and $b$ are no longer sliding a line up and down. They're rotating it *and* shifting it, searching a 2D space instead of a 1D line, as the gradient vector

$$\nabla L = \begin{bmatrix} \dfrac{\partial L}{\partial m} \\[6pt] \dfrac{\partial L}{\partial b} \end{bmatrix}$$

points the way down.

```python
    def predict(self, X):
        return self.m * X + self.b
```

Once `fit()` has finished, no more learning happens. `predict()` simply plugs the final, learned $m$ and $b$ into $y = mx + b$ for any new input.

## Cells 11–13 — Putting It to the Test

```python
gd = GDRegressor(0.001, 50)
```

A learning rate of `0.001` — deliberately small and cautious — and only `50` epochs.

```python
gd.fit(X_train, y_train)
```

Inside this single call, the loop repeats fifty times: predict, measure the error, compute both gradients, update both parameters. Printed at the end:

```
28.159367347119066 -2.3004574196824854
```

Compare that against sklearn's closed-form answer from Cell 8 — $m \approx 28.126$, $b \approx -2.271$. Fifty epochs of nothing but repeated arithmetic landed within a fraction of a percent of the exact solution.

```python
y_pred = gd.predict(X_test)

from sklearn.metrics import r2_score
r2_score(y_test, y_pred)
```

The result comes out to roughly **0.634** — essentially identical to sklearn's 0.6345 from Cell 9.

> *"If a fifty-line class matches what `LinearRegression()` does internally, what exactly was the 'magic' inside sklearn to begin with?"*

There wasn't any. There was a loop, two gradients, and a lot of repeated arithmetic — precisely what's sitting inside `GDRegressor` right now.

## 🧪 Sanity Check

The two gradient formulas here differ by exactly one factor: `* X.ravel()`. That single difference is the entire distinction between "how should the intercept shift" and "how should the slope rotate." Miss that multiplication in the derivative for $m$, and the model silently degrades back into the single-parameter walker from the earlier notebook — technically running, but blind to half the parameter space.

## 🔗 ML Bridge

This is the exact mechanism running underneath the stroke prediction system's training loop, just scaled up in dimensionality. Where `GDRegressor` updates two numbers — `self.m` and `self.b` — a model predicting stroke risk from age, glucose level, BMI, hypertension, and more updates a whole vector of weights, one gradient per feature, all computed and applied in the same pass. The loop structure, `for i in range(epochs): compute gradients, update parameters`, doesn't change at all. Only the number of parameters walking down the bowl does.

## 🌀 Deepest Realization

Two gradients, computed from the same residuals, differing by a single multiplication — that's the entire leap from a model that can only slide a line up and down to one that can also rotate it. Nothing about the underlying idea grew more complicated. The walker just gained a second direction it's allowed to move in, and the update rule, unchanged since the very first single-variable notebook, simply got applied twice instead of once.

## ✅ Final Takeaway

> *"Once you understand one gradient, understanding two isn't harder — it's just the same question, asked once for every direction the line is allowed to move."*
