# 🧺 The Committee That Studied From Different Pages: Bagging, Explained

> *"One model can be unstable. So train many versions of it on slightly different data, let each one answer, and combine the answers. The random differences partly cancel out."*

---

## 🌳 The Student Who Memorized the Textbook

Imagine you train a single, fully grown decision tree on your dataset.

It keeps splitting until it fits the training rows almost perfectly. Training accuracy: **100%**. It looks brilliant.

Then you change the training data *slightly*: a few rows swapped in, a few swapped out. The tree that comes out is a **different tree**, and it gives different predictions on the same new patient.

That is the problem in one sentence: this model is **sensitive to the exact data it saw**. In the language of the bias–variance tradeoff, it has:

- **Low bias**: it is flexible enough to capture the real pattern.
- **High variance**: its answers swing when the training data wiggles.

> 🤔 *"Instead of trusting one temperamental tree, can I ask a whole committee?"*

Yes, and that is exactly what **Bagging** does. But the committee only helps if its members *disagree in useful ways*. Five copies of the same student who studied the same page will make the same mistake five times.

So the real question becomes: **how do I make five students who studied different pages of the same book?**

---

## ✂️ Two Words Hidden Inside One

**Bagging = Bootstrap + Aggregating**

| Word | What it does |
|---|---|
| **Bootstrap** | Create many *different* training datasets from the one you have |
| **Aggregation** | Combine the predictions of the models trained on them |

```
Original Dataset
       │
       ├── Bootstrap Sample 1 → Model 1
       ├── Bootstrap Sample 2 → Model 2
       ├── Bootstrap Sample 3 → Model 3
       ├── Bootstrap Sample 4 → Model 4
       └── Bootstrap Sample 5 → Model 5
                         │
                         ▼
                Combine Predictions
                         │
                         ▼
                      Output
```

## 🎲 Drawing Cards and Putting Them Back

> 🤔 *"What exactly is a bootstrap sample, and what does 'with replacement' mean?"*

Your original dataset has 5 rows:

```
A  B  C  D  E
```

To build one bootstrap sample, you draw **5 times**. After each draw you **put the row back** before drawing again. That put-it-back step is **sampling with replacement**.

One possible result:

```
A  C  C  E  A
```

Look at what happened:

- **A** appeared twice.
- **C** appeared twice.
- **B** and **D** never appeared.

So a bootstrap sample is **the same size as the original**, but it contains **duplicates and omissions**. If your dataset has 10,000 rows, every bootstrap sample also has 10,000 rows. They are just *randomly different* 10,000 rows.

Each model gets its own such sample:

```
D1 → Model 1
D2 → Model 2
D3 → Model 3
D4 → Model 4
D5 → Model 5
```

Every model now sees a slightly different version of reality. That is the **diversity** the committee needed.

### 🔢 How much of the data does each model actually see?

You can derive this yourself, step by step. Take any one row in a dataset of $n$ rows.

1. On a single draw, the chance this row is **not** picked is $1-\frac{1}{n}$.
2. You draw $n$ times, independently (because of replacement). The chance it is **never** picked is:

$$\left(1-\frac{1}{n}\right)^{n}$$

3. As $n$ grows, this approaches $\frac{1}{e}\approx 0.368$.
4. So the chance the row **is** picked at least once is about:

$$1-\frac{1}{e}\approx 0.632$$

**Meaning:** each bootstrap sample contains roughly **63.2%** of the *distinct* rows. The other **~36.8%** are left out. These left-out rows are called **out-of-bag (OOB)** rows, and they become useful later as a free validation set.

*I checked this by simulation:* for $n=10$ the observed fraction was 0.655 (formula: $1-(0.9)^{10}=0.651$), and for $n=1000$ and $n=10000$ it was 0.632 (see the fact-check section below).

## 🗳️ The Committee Votes

> 🤔 *"After training, how do the models combine their answers?"*

A new data point $X$ arrives. You send the **same $X$** to every model:

```
              New Data X
                  │
     ┌────┬───────┼───────┬────┐
     ▼    ▼       ▼       ▼    ▼
    M1   M2      M3      M4   M5
     │    │       │       │    │
     A    B       A       A    A
```

**Classification → majority vote**

```
A → 4 votes
B → 1 vote
Final prediction = A
```

**Regression → average**

Predictions: 100, 110, 105, 95, 90

$$\frac{100+110+105+95+90}{5}=100$$

| Problem | Aggregation |
|---|---|
| Classification | Majority vote |
| Regression | Average |

So the two halves of the name are now complete:

```
BOOTSTRAP (different data)  +  AGGREGATION (combine answers)
                    ↓
                 BAGGING
```

## 📏 Why Does Averaging Help? Five People With a Ruler

> 🤔 *"Why do we need multiple models? Why not just one good one?"*

Five people measure the same table:

```
99 cm   101 cm   100 cm   98 cm   102 cm
```

No single measurement is perfect. But the average is **100 cm**, because the random errors push in different directions and partly cancel.

Models work the same way. Suppose five models make these errors on the same point:

```
+10   −8   +5   −7   +2
```

Their sum is $10-8+5-7+2=2$, so the **average error is $2/5=0.4$**. Individually the models were off by up to 10. Together, they are off by 0.4.

That is **variance reduction**. Bagging does not make any single tree smarter. It makes the **final answer steadier**.

### 🧮 The math behind "cancel out", derived step by step

Suppose each of $n$ models makes a prediction with variance $\sigma^2$.

**Case 1: the errors are completely independent.**

$$\text{Var}\left(\frac{1}{n}\sum_{i=1}^{n} \hat f_i\right)=\frac{1}{n^2}\cdot n\sigma^2=\frac{\sigma^2}{n}$$

Five models → one-fifth of the variance. Beautiful, but unrealistic. Models trained on overlapping data are never fully independent.

**Case 2: every pair of models has correlation $\rho$.**

The variance of a sum includes the $n$ variance terms plus $n(n-1)$ covariance terms, each equal to $\rho\sigma^2$:

$$\text{Var}\left(\frac{1}{n}\sum_{i=1}^{n} \hat f_i\right)=\frac{1}{n^2}\Big[n\sigma^2+n(n-1)\rho\sigma^2\Big]=\frac{\sigma^2}{n}+\frac{(n-1)}{n}\rho\sigma^2$$

Rearranging $\frac{(n-1)}{n}\rho\sigma^2=\rho\sigma^2-\frac{\rho\sigma^2}{n}$ gives:

$$\boxed{\text{Var}=\rho\sigma^2+\frac{(1-\rho)\,\sigma^2}{n}}$$

Read this formula slowly, because it is the whole story:

- Adding more models ($n\to\infty$) kills the **second** term.
- The **first** term, $\rho\sigma^2$, **never goes away**. It is the floor set by how correlated the models are.

*Worked check with $n=5$, $\sigma^2=1$* (I confirmed these by simulation):

| Correlation $\rho$ | Formula $\rho+\frac{1-\rho}{5}$ | Simulated |
|---|---|---|
| 0 | 0.20 | 0.20 |
| 0.3 | 0.44 | 0.44 |
| 0.7 | 0.76 | 0.76 |
| 1.0 | 1.00 | 1.01 |

At $\rho=1$ (identical models), the committee has **zero** benefit. At $\rho=0$ you get the full $\frac{1}{n}$. This is why the sentence

> **More models help, but more *diverse* models help far more.**

is not a slogan. It is this formula.

> ⚠️ **Honest caveat:** this formula models predictions as identically distributed with a common pairwise correlation. It is the standard intuition for *why* averaging helps, not an exact proof about bagged trees specifically.

## 🪞 The Claim: "This Is Just the Reciprocal of Voting"

Here is where your own thinking enters the story. You compared Bagging with the Voting ensemble you had already learned, and wrote:

> *"This is just the reciprocal of voting.*
> *Voting: same dataset, different models.*
> *Bagging: same model, but different subsets of the same dataset."*

That is a genuinely useful mental model, and it captures the core difference. Two refinements make it exact:

1. **"Reciprocal" is a great intuition but not a literal word.** There is no mathematical inverse here. The better word is **mirror**: both methods aim at *diversity among the base models*, and they pull the opposite lever.
2. **"Same model" is the usual case, not a rule.** scikit-learn's `BaggingClassifier` defaults to a decision tree, but you can pass in any estimator. Its own docs show an example with `SVC()` as the base model.

So the clean version is:

| | **Voting** | **Bagging** |
|---|---|---|
| Training data | Same dataset | Different bootstrap samples |
| Base models | Different algorithms | Usually the same algorithm |
| Source of diversity | Change the **model** | Change the **data** |
| Combination | Vote / average | Vote / average |
| Main purpose | Combine complementary models | Reduce variance |

```
VOTING                                BAGGING
Same Dataset                          Same Original Dataset
     │                                        │
 ┌───┼────┬────┐                        ┌────┼────┬────┐
 ▼   ▼    ▼    ▼                        ▼    ▼    ▼    ▼
LR  KNN  SVM  DT                       D1   D2   D3   D4
 │   │    │    │                        │    │    │    │
 └───┴────┴────┘                        ▼    ▼    ▼    ▼
       ↓                              Tree Tree Tree Tree
     Vote                               └────┴────┴────┘
                                              ↓
                                            Vote
```

$$\boxed{\text{Voting: same data → different models}}\qquad\boxed{\text{Bagging: different samples → (usually) same model type}}$$

And here is the twist that makes the picture complete. Earlier in this series you saw Voting with the **same algorithm and different hyperparameters** (the SVM `degree=1..5` idea). That means diversity has **two independent knobs**:

- the **model knob** (algorithm or hyperparameters), turned by Voting;
- the **data knob** (which rows each model sees), turned by Bagging.

They are not rivals. They are two axes of the same idea.

> 🔎 **A small relative worth knowing:** scikit-learn's docs note that if you draw random subsets *without* replacement, the method is called **Pasting**, and only *with* replacement is it called **Bagging**.

## 🧊 Sanity Check: Does It Really Work?

Words are cheap, so here is a real run. I generated a synthetic classification dataset (`make_classification`, 2000 rows, 20 features), took 30 different random training subsets of 750 rows, and trained a **single decision tree** and a **Bagging of 50 trees** on each. Both were tested on the same held-out 500 rows.

| | Single Tree | Bagging (50 trees) |
|---|---|---|
| Mean test accuracy | 0.818 | 0.891 |
| Std of accuracy across training sets | 0.020 | 0.010 |
| Average variance of a test point's predicted label across training sets | 0.104 | 0.039 |

Two things happened, exactly as the theory predicts:

1. The bagged model is **more accurate on average**.
2. It is **about half as sensitive** to which training subset it got.

An out-of-bag check on a separate run (100 trees, 1500 training rows) gave OOB accuracy of **0.885**, close to the **0.916** test accuracy. Those OOB rows needed no separate validation split.

> ⚠️ **Scope of this evidence:** this is one synthetic dataset, one seed, one run of mine. It illustrates the effect. It is not a general guarantee for every dataset.

```python
from sklearn.ensemble import BaggingClassifier
from sklearn.tree import DecisionTreeClassifier

bag = BaggingClassifier(
    estimator=DecisionTreeClassifier(),  # same model type, many copies
    n_estimators=100,                    # committee size
    bootstrap=True,                      # sample WITH replacement (the default)
    oob_score=True,                      # score using the left-out ~36.8% rows
    random_state=0,
)
bag.fit(X_train, y_train)
print(bag.oob_score_, bag.score(X_test, y_test))
```

## 🌉 ML Bridge: From Bagging to Random Forest

Everything above leads to one conclusion. Bagging is a **template**, and decision trees are its most natural base model, because a deep tree is exactly the low-bias, high-variance student that a committee can calm down.

```
Bagging
   ↓
Many deep decision trees, each on a bootstrap sample
   ↓
Add extra randomness in which features each split may consider
   ↓
Aggregate predictions
   ↓
Random Forest
```

So when you meet Random Forest, don't treat it as a stranger. It is the Bagging idea plus one more source of diversity. (That feature-randomness detail comes from the lecture and from general knowledge. I did not re-verify it against a source in this session, and you'll meet it formally in the next chapter.)

If your Stroke Prediction tree ever gives noticeably different results after you change the train/test split, that is the high-variance symptom this chapter treats.

## 🌀 Deepest Realization

Bagging never improves **any individual model**. Every tree in the committee is still as overfit and as temperamental as before.

The improvement lives **between** the models, in the fact that their mistakes are not identical. The system gets its strength from **disagreement that cancels**, not from any member being better.

```
High-variance model
       ↓
Different bootstrap samples
       ↓
Different trees
       ↓
Different errors
       ↓
Aggregate
       ↓
Errors partly cancel
       ↓
Lower variance → more stable predictions
```

And the floor of that improvement is set by one number, $\rho$, how similar the committee members still are to each other.

## ✅ Final Takeaway

> **"Bagging doesn't build a smarter model; it builds a calmer one. Give many copies of an unstable model different samples of the same data, let them vote, and their mistakes, which no longer line up, partly cancel. Voting changes the model to get diversity; Bagging changes the data. And the less alike the committee members are, the more the committee is worth."**
