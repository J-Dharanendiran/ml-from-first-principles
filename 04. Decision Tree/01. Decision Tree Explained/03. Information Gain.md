# ⚖️ The Scale That Weighs Before and After

> *"Entropy tells you how mixed a room is. Information Gain tells you how much cleaner it got after you moved the furniture."*

---

You now have a ruler — Entropy — that can measure how impure any single node is. But a ruler alone doesn't build a tree. The tree still has to answer the one question every chapter so far has been circling:

> **Which feature should become the next splitting feature?**

**Information Gain** is the answer. It's introduced as a metric for measuring the **decrease in Entropy after partitioning the data using an attribute/feature** — the direct bridge between "how impure is this?" and "which split actually helps?"

## 🧩 Why Entropy Alone Isn't Enough

Say your dataset has `Feature 1`, `Feature 2`, `Feature 3`, and a `Target`. You could split on any of them. But which produces the *best* split?

> **A good split should make the resulting child datasets more pure than the original dataset.**

So the comparison you need is:

```
Entropy before splitting
        ↓
       SPLIT
        ↓
Entropy after splitting
```

If Entropy drops significantly, the split earned its keep. That drop **is** Information Gain.

## 🔢 The Core Idea, in Numbers

Suppose the parent has:
$$Entropy(Parent) = 0.97$$

You try a split. The children come back with a combined weighted Entropy of:
$$0.40$$

$$
Information\ Gain = 0.97 - 0.40
$$
$$
\boxed{IG = 0.57}
$$

```
Before split → Entropy = 0.97
   SPLIT
After split → Weighted Entropy = 0.40
   ↓
Information Gain = 0.57
```

## ⚖️ Why You Can't Just Average the Children

> *"If I have two children with Entropy 0 and Entropy 1, isn't the answer just 0.5?"*

No — and this is the trap. Say the parent has 10 observations, splitting into:
```
Child 1 → 6 observations, Entropy = 0
Child 2 → 4 observations, Entropy = 1
```

$$\frac{0+1}{2} = 0.5 \quad \text{— wrong.}$$

Child 1 holds **6/10 = 60%** of the data; Child 2 holds only **4/10 = 40%**. The bigger child should count for more. So instead of a plain average, you take a **weighted** one:

$$
Weighted\ Child\ Entropy = 0.6(0) + 0.4(1) = 0 + 0.4
$$
$$
\boxed{0.4}
$$

Not 0.5. **0.4.** The size of each child matters just as much as its purity.

## 📐 The Complete Formula

$$
\boxed{
IG(Parent, Feature) = Entropy(Parent) - \sum_j \left(\frac{|Child_j|}{|Parent|} \times Entropy(Child_j)\right)
}
$$

Two pieces:

- **$Entropy(Parent)$** — impurity *before* the split.
- **$\sum_j \frac{|Child_j|}{|Parent|} \times Entropy(Child_j)$** — the weighted average impurity *after* the split.

$$
\boxed{Information\ Gain = \text{Entropy Before} - \text{Weighted Entropy After}}
$$

That's the whole concept, in one line.

## 🧮 A Small Worked Example First

Parent: 10 observations, 5 Yes / 5 No → $P(Yes)=P(No)=0.5$ → $Entropy(Parent) = 1$.

Split produces:
```
Child A: 6 rows → 6 Yes, 0 No  → Entropy(A) = 0
Child B: 4 rows → 2 Yes, 2 No  → Entropy(B) = 1
```

Weighted Entropy:
$$
\frac{6}{10}(0) + \frac{4}{10}(1) = 0 + 0.4 = 0.4
$$

$$
IG = 1 - 0.4 = \boxed{0.6}
$$

That 0.6 means Entropy fell from 1 (maximally mixed) to 0.4 — the split genuinely organized the data. Two edge cases worth holding onto:

- **A useless split:** if the weighted child Entropy stays at 1, $IG = 1-1 = 0$. No information gained, no progress made.
- **A perfect split:** if both children end up pure ($Entropy=0$ each), weighted child Entropy is 0, so $IG = 1-0 = 1$ — the maximum possible under this setup. Mixed data became pure data in a single move.

## 🏆 Comparing Candidate Features

With several features, you calculate $IG$ for each and pick the winner:

| Feature | Parent Entropy | Weighted Child Entropy | Information Gain |
|---|---:|---:|---:|
| Feature A | 1.00 | 0.60 | **0.40** |
| Feature B | 1.00 | 0.30 | **0.70** |
| Feature C | 1.00 | 0.80 | **0.20** |

$$0.70 > 0.40 > 0.20$$

**Feature B wins** — it produces the largest reduction in Entropy, so it becomes the splitting feature. This is the entire selection rule: **calculate Information Gain for every candidate column, and choose the one with the highest value.**

## 🔁 It Happens Again, and Again

Selecting the root is only step one. Once `Outlook` (say) becomes the root:

```
              Outlook
             /   |    \
          Sunny Rain Overcast
```

the tree doesn't stop. For each branch — say the `Rain` subset — it asks the exact same question all over again, this time restricted to the remaining features:

```
Rain subset
     ↓
Calculate IG
     ↓
Choose best remaining feature
     ↓
Split
```

The full recursive shape looks like:

```
                 Full Dataset
                      |
              Calculate IG
                      |
              Best feature
                      |
                    Split
                 /         \
                /           \
          Subset A        Subset B
             |                |
       Calculate IG      Calculate IG
             |                |
       Best feature      Best feature
             |                |
           Split            Split
             ↓                ↓
            ...              ...
```

Entropy and Information Gain aren't a one-time calculation — they're the engine that fires at **every single node**, all the way down.

## 🎾 Now, the Full Example: Play Tennis, All the Way Through

Everything above was the theory. Here's the *actual* 14-row Play Tennis dataset, worked completely — Entropy → every candidate split → weighted child Entropy → Information Gain → the winning feature. First, the raw data itself:

| Outlook  | Temperature | Humidity | Windy | PlayTennis |
| -------- | ----------- | -------- | ----- | ---------- |
| Sunny    | Hot         | High     | False | No         |
| Sunny    | Hot         | High     | True  | No         |
| Overcast | Hot         | High     | False | Yes        |
| Rainy    | Mild        | High     | False | Yes        |
| Rainy    | Cool        | Normal   | False | Yes        |
| Rainy    | Cool        | Normal   | True  | No         |
| Overcast | Cool        | Normal   | True  | Yes        |
| Sunny    | Mild        | High     | False | No         |
| Sunny    | Cool        | Normal   | False | Yes        |
| Rainy    | Mild        | Normal   | False | Yes        |
| Sunny    | Mild        | Normal   | True  | Yes        |
| Overcast | Mild        | High     | True  | Yes        |
| Overcast | Hot         | Normal   | False | Yes        |
| Rainy    | Mild        | High     | True  | No         |

Every number in the walkthrough below — every probability, every entropy, every weighted average — comes directly from counting rows in this table.

### Step 1 — Count the Target Column

The target is `PlayTennis`, with 14 total observations:

| Class | Count | Probability |
|---|---:|---:|
| Yes | 9 | $9/14$ |
| No | 5 | $5/14$ |
| **Total** | **14** | **1** |

$$
P(Yes) = \frac{9}{14} \approx 0.6429, \qquad P(No) = \frac{5}{14} \approx 0.3571
$$

### Step 2 — Parent Entropy

$$
Entropy(S) = -P(Yes)\log_2 P(Yes) - P(No)\log_2 P(No)
$$
$$
= -(0.6429)\log_2(0.6429) - (0.3571)\log_2(0.3571)
$$
$$
\boxed{Entropy(S) \approx 0.9403}
$$

That's close to the maximum of 1 but not quite there — the dataset is mixed (9 Yes, 5 No), just not perfectly balanced.

### Step 3 — Four Candidates: Outlook, Temperature, Humidity, Windy

The tree needs to evaluate all four and pick whichever gives the highest Information Gain.

---

#### 🌤️ Feature 1: Outlook (Sunny / Overcast / Rainy)

**Sunny** — 2 Yes, 3 No out of 5:
$$
P(Yes)=0.4, \ P(No)=0.6 \ \Rightarrow \ H(Sunny) = -\tfrac25\log_2\tfrac25 - \tfrac35\log_2\tfrac35 \approx \boxed{0.9710}
$$

**Overcast** — 4 Yes, 0 No out of 4:
$$
P(Yes)=1, \ P(No)=0 \ \Rightarrow \ H(Overcast) = -(1)\log_2(1)-(0)\log_2(0) = \boxed{0}
$$
A perfectly pure node — *every* Overcast day says Yes.

**Rainy** — 3 Yes, 2 No out of 5:
$$
P(Yes)=0.6, \ P(No)=0.4 \ \Rightarrow \ H(Rainy) = -\tfrac35\log_2\tfrac35 - \tfrac25\log_2\tfrac25 \approx \boxed{0.9710}
$$

**Weighted Entropy for Outlook** (weights $5/14$, $4/14$, $5/14$):
$$
\frac{5}{14}(0.9710) + \frac{4}{14}(0) + \frac{5}{14}(0.9710) = 0.3468 + 0 + 0.3468 \approx \boxed{0.6935}
$$

**Information Gain:**
$$
IG(Outlook) = 0.9403 - 0.6935 \approx \boxed{0.2467}
$$

---

#### 🌡️ Feature 2: Temperature (Hot / Mild / Cool)

**Hot** — 2 Yes, 2 No out of 4:
$$
P(Yes)=P(No)=0.5 \ \Rightarrow \ H(Hot) = \boxed{1} \quad \text{(maximum entropy, perfectly balanced)}
$$

**Mild** — 4 Yes, 2 No out of 6:
$$
H(Mild) = -\tfrac46\log_2\tfrac46 - \tfrac26\log_2\tfrac26 \approx \boxed{0.9183}
$$

**Cool** — 3 Yes, 1 No out of 4:
$$
H(Cool) = -\tfrac34\log_2\tfrac34 - \tfrac14\log_2\tfrac14 \approx \boxed{0.8113}
$$

**Weighted Entropy for Temperature** (weights $4/14$, $6/14$, $4/14$):
$$
\frac{4}{14}(1) + \frac{6}{14}(0.9183) + \frac{4}{14}(0.8113)
$$
$$
= 0.2857 + 0.3936 + 0.2318 \approx \boxed{0.9111}
$$

**Information Gain:**
$$
IG(Temperature) = 0.9403 - 0.9111 \approx \boxed{0.0292}
$$

Barely a dent in the impurity.

---

#### 💧 Feature 3: Humidity (High / Normal)

**High** — 3 Yes, 4 No out of 7:
$$
H(High) = -\tfrac37\log_2\tfrac37 - \tfrac47\log_2\tfrac47 \approx \boxed{0.9852}
$$

**Normal** — 6 Yes, 1 No out of 7:
$$
H(Normal) = -\tfrac67\log_2\tfrac67 - \tfrac17\log_2\tfrac17 \approx \boxed{0.5917}
$$

**Weighted Entropy for Humidity** (both groups weight $7/14$):
$$
\frac{7}{14}(0.9852) + \frac{7}{14}(0.5917) = 0.4926 + 0.2958 \approx \boxed{0.7885}
$$

**Information Gain:**
$$
IG(Humidity) = 0.9403 - 0.7885 \approx \boxed{0.1518}
$$

---

#### 🌬️ Feature 4: Windy (False / True)

**Windy = False** — 6 Yes, 2 No out of 8:
$$
P(Yes)=0.75, \ P(No)=0.25 \ \Rightarrow \ H(False) = -0.75\log_2(0.75) - 0.25\log_2(0.25) \approx \boxed{0.8113}
$$

**Windy = True** — 3 Yes, 3 No out of 6:
$$
P(Yes)=P(No)=0.5 \ \Rightarrow \ H(True) = \boxed{1}
$$

**Weighted Entropy for Windy** (weights $8/14$, $6/14$):
$$
\frac{8}{14}(0.8113) + \frac{6}{14}(1) = 0.4636 + 0.4286 \approx \boxed{0.8922}
$$

**Information Gain:**
$$
IG(Windy) = 0.9403 - 0.8922 \approx \boxed{0.0481}
$$

---

### Step 4 — Compare All Four

| Feature | Weighted Child Entropy | Information Gain |
|---|---:|---:|
| **Outlook** | 0.6935 | **0.2467** ← highest |
| **Humidity** | 0.7885 | **0.1518** |
| **Windy** | 0.8922 | **0.0481** |
| **Temperature** | 0.9111 | **0.0292** |

$$
\boxed{0.2467 > 0.1518 > 0.0481 > 0.0292}
$$

**Outlook wins**, by a clear margin. The tree's reasoning, in plain words: *"if I split on Outlook, I reduce uncertainty the most."*

```
                    Outlook
                 /     |      \
              Sunny  Overcast  Rainy
```

**Outlook becomes the Root Node.**

### Step 5 — It's Already Half-Finished

Look closely at the `Overcast` branch: 4 Yes, 0 No → $Entropy = 0$. It's already perfectly pure — nothing left to decide. It becomes a **leaf** immediately:

```
                 Outlook
              /     |       \
           Sunny  Overcast   Rainy
                    |
                   Yes
```

`Sunny` and `Rainy`, however, are still mixed. So the exact same process — Entropy, candidate splits, weighted child Entropy, Information Gain — runs **again**, independently, inside each of those subsets, using whichever features remain:

```
Parent Dataset
      │
      ▼
Calculate Entropy
      │
      ▼
Try every possible feature
      │
      ▼
Calculate Information Gain
      │
      ▼
Choose highest IG
      │
      ▼
Split
      │
      ├───────────────┐
      ▼               ▼
   Pure node       Impure node
      │               │
    Leaf          Calculate IG again
                      │
                      ▼
                    Split
```

## 🩺 Sanity Check

Keep these two questions permanently separate:

| | Question it answers | For Play Tennis |
|---|---|---|
| **Entropy** | "How impure is *this* dataset, right now?" | $0.9403$ |
| **Information Gain** | "If I split using *this* feature, how much does that impurity drop?" | $IG(Outlook)=0.2467$, the winner |

Entropy is a snapshot. Information Gain is a comparison between two snapshots — before and after — for a *specific* candidate split.

## 🌉 ML Bridge

This worked example is the ID3-style approach to tree-building: pick the split with maximum Information Gain, recurse, repeat. It's worth knowing that this isn't the only impurity criterion in use — modern implementations (like scikit-learn's `DecisionTreeClassifier`) also support **Gini impurity** and **log loss** as alternatives to Entropy, each with slightly different behavior but the same underlying goal: find the split that best separates the classes.

## 🌀 Deepest Realization

Notice what actually made Outlook win: it wasn't the feature with the "best-looking" individual branch — `Temperature = Hot` was a coin flip (Entropy 1), just like `Outlook = Sunny` was nearly one (0.9710). What won was the *portfolio effect*: Outlook happened to contain one branch, `Overcast`, that was **perfectly pure** and substantial (4 of 14 rows), and that single clean branch was enough to drag the weighted average down further than any other feature managed. Information Gain doesn't reward a feature for being good everywhere — it rewards a feature for being good on weighted average, even if that means one spectacular branch is doing most of the work.

## ✅ Final Takeaway

> *"Information Gain is Entropy before the split minus the weighted Entropy after it — and the feature that maximizes that gain becomes the split, at every node, recursively, until every branch either becomes pure or runs out of features to try."*
