# 🎒 The Exam Nobody Studied For: Out-of-Bag (OOB) Evaluation in Random Forest

> *"For every training row, ask only the trees that never saw it. Their answers are an honest test, and you get it for free."*

---

## 🧺 The Leftovers From Bootstrap Sampling

Recall what a bootstrap sample does. Each tree trains on rows drawn **with replacement**, so about **63.2%** of the distinct rows land in its sample and about **36.8%** are left out.

Those left-out rows are called that tree's **out-of-bag (OOB)** rows. The tree never saw them during training, which makes them an honest test set for that tree.

```
Training data
      ↓
Bootstrap sampling
      ↓
┌───────────┬───────────┬───────────┐
Tree 1      Tree 2      Tree 3      ...
  ↓           ↓           ↓
OOB rows    OOB rows    OOB rows
  ↓           ↓           ↓
predictions predictions predictions
       └─────────┬─────────┘
                 ↓
           OOB predictions
                 ↓
             OOB score
```

So a Random Forest can evaluate itself, without carving out a separate validation set. This chapter answers the question that immediately follows:

> 🤔 *"I never gave it a row number. How did `oob_score_` return a value?"*

---

## 🛠️ Step One: Switch It On

```python
from sklearn.ensemble import RandomForestRegressor

rf = RandomForestRegressor(
    n_estimators=100,
    bootstrap=True,      # OOB needs bootstrap sampling
    oob_score=True,      # turn on OOB evaluation
    random_state=42,
    n_jobs=-1,
)
rf.fit(X_train, y_train)

print("OOB Score:", rf.oob_score_)
```

For a regression forest, `oob_score_` is the coefficient of determination, **R²**, by default. An output of `0.71` means the OOB predictions achieved an R² of about 0.71.

(For a classifier, `oob_score_` is **accuracy** by default.)

---

## 🔍 Step Two: Why No Row Number Was Needed

> 🤔 *"I didn't say 'evaluate row 17.' How does it know what to do?"*

Because OOB evaluation is **not a single-row function**. It runs automatically, for **every training row**, while the forest is being fit. During `fit()`, the forest keeps track of which rows each tree's bootstrap sample contained, so it already knows which trees never saw which rows.

### 🧪 A five-row toy example

Training rows: `A  B  C  D  E`. Three trees draw bootstrap samples:

```
Tree 1 sample:  A  C  C  E  B     →  OOB for Tree 1 = D
Tree 2 sample:  A  A  D  E  E     →  OOB for Tree 2 = B, C
Tree 3 sample:  B  C  E  A  A     →  OOB for Tree 3 = D
```

Now take **one row**, D, and ask: which trees did *not* see it?

```
Tree 1 → did NOT see D  ✅
Tree 2 → DID see D      ❌
Tree 3 → did NOT see D  ✅
```

Only Tree 1 and Tree 3 are allowed to predict D. Suppose they say 150 and 156:

$$\text{OOB prediction}(D)=\frac{150+156}{2}=153$$

If D's actual target is 155, the OOB prediction is 153. Close, and honest, since neither tree ever trained on D.

---

## 🔁 Step Three: Do That For Every Row

The forest repeats the same procedure for all training rows:

```
Row 1   → find trees that didn't see it → average their predictions → OOB prediction
Row 2   → find trees that didn't see it → average their predictions → OOB prediction
Row 3   → ...
...
Row 400 → ...
```

That produces one OOB prediction per training row, stored in `rf.oob_prediction_`:

```
             Actual       OOB Prediction
Row 1          152             149
Row 2           87              91
Row 3          203             198
Row 4          115             117
...
Row 400        176             171
```

I checked this on a real run (400 training rows, 100 trees):

- `len(rf.oob_prediction_)` was **400**, the same as `len(y_train)`.
- For row 17, the actual target was −36.67 and the OOB prediction was −23.20, averaged over the **43 trees** that did not see that row.
- Across rows, the number of trees that did not see a given row ranged from 21 to 51, averaging **37.1** (the theory predicts about $100\times0.368=36.7$).

I also rebuilt every OOB prediction **by hand**, looping over the trees, taking each tree's left-out rows, and averaging its predictions. My manual array matched `oob_prediction_` with a maximum difference of **0.0**. So the mechanism described above is exactly what scikit-learn does.

---

## 🧮 Step Four: From 400 Predictions to One Number

> 🤔 *"So the value I saw is the aggregation of all those row predictions, right?"*

**Almost.** The first half of your picture is exactly right: row by row, the eligible trees predict, and their predictions are aggregated into one OOB prediction per row. The correction is the second half:

> `oob_score_` is **not** an aggregation of the predictions themselves. It is an **evaluation metric computed from** all the row-level OOB predictions, compared against the true targets.

There are **two different aggregations** in the story:

```
AGGREGATION #1 (within each row, averaging trees):
   Tree 2 → 150
   Tree 5 → 155
   Tree 8 → 148
   Tree 11 → 152
        ↓ average
   OOB prediction for this row = 151.25

AGGREGATION #2 (across rows, an evaluation metric):
   Row 1 → actual vs OOB prediction
   Row 2 → actual vs OOB prediction
   ...
   Row N → actual vs OOB prediction
        ↓ compute R²
   ONE number = oob_score_
```

The full flow:

```
                     X_train, y_train
                           │
                 ┌───────────────────┐
                 │ Random Forest fit │
                 └─────────┬─────────┘
                           │
                Bootstrap sampling
                           │
          ┌────────────────┼────────────────┐
       Tree 1           Tree 2           Tree 3
          │                │                │
       OOB rows         OOB rows         OOB rows
          └────────────────┼────────────────┘
                           ↓
                For EACH training row:
              Find trees that didn't see it
                           ↓
                 Get their predictions
                           ↓
                    Aggregate them
                           ↓
                 OOB prediction array
                           ↓
             Compare with actual y_train
                           ↓
                       R² score
                           ↓
                   rf.oob_score_
```

The distinction to keep:

| Attribute | What it is |
|---|---|
| `rf.oob_prediction_` | One OOB prediction **per training row** |
| `rf.oob_score_` | **One overall score** (R²) calculated from all of those predictions |

---

## ✅ Step Five: Reproduce It Yourself

The best way to trust it is to compute it manually:

```python
from sklearn.metrics import r2_score

manual_oob_r2 = r2_score(y_train, rf.oob_prediction_)

print("Manual OOB R²:  ", manual_oob_r2)
print("Built-in OOB R²:", rf.oob_score_)
```

On my run, both printed **0.8275**, identical.

---

## 📊 Step Six: OOB vs Test vs Training

Now compare three different numbers:

```python
from sklearn.metrics import r2_score

y_pred = rf.predict(X_test)
print("OOB R²: ", rf.oob_score_)
print("Test R²:", r2_score(y_test, y_pred))
```

On my run (synthetic regression data, 500 rows, 400 for training):

| Number | R² | What it measures |
|---|---|---|
| **Training R²** (`rf.score(X_train, y_train)`) | **0.977** | Rows the trees *did* train on, misleadingly optimistic |
| **OOB R²** (`rf.oob_score_`) | **0.828** | Each row judged only by trees that never saw it |
| **Test R²** | **0.849** | Completely unseen held-out data |

This is the whole point of OOB. Training R² of 0.977 looks superb but is inflated because the trees memorized their own rows. OOB R² (0.828) lands close to the test R² (0.849), which is why OOB is a good internal estimate of generalization. The two won't match exactly: OOB uses only about 37 trees per row (not the full forest), and the test set is a different sample.

```
Training data ──→ bootstrap ──→ trees  ──→ OOB predictions ──→ OOB R²     (internal check)

Completely unseen test data ──→ full forest ──→ test predictions ──→ Test R²   (final check)
```

OOB is an excellent internal diagnostic. Your held-out test set is still the right place for the final evaluation.

---

## 🪶 What If There Are Too Few Trees?

> 🤔 *"Does every row always get an OOB prediction?"*

No. A row only gets one if **at least one tree left it out**. The chance that a given row is in *every* tree's sample is $0.632^{n}$, which is large for small forests and negligible for large ones:

| `n_estimators` | Rows with no OOB tree (of 400, my run) | Expected $400\times0.632^n$ | `oob_score_` |
|---|---|---|---|
| 5 | 36 | ≈ 40 | 0.586 |
| 10 | 3 | ≈ 4 | 0.724 |
| 100 | 0 | ≈ 0 | 0.826 |

With few trees, scikit-learn warns that some inputs do not have OOB scores. In my run, those rows showed up in `oob_prediction_` as exactly **0**, which drags the score down: 0.586 with 5 trees versus 0.826 with 100. With `n_estimators=100`, the chance of a row having no OOB tree is about $10^{-20}$, so this is not a practical concern at normal forest sizes.

## 🧩 Bonus: Classifiers and Custom Metrics

**Classification.** `RandomForestClassifier(oob_score=True)` reports **accuracy**, and exposes `oob_decision_function_`, the per-row OOB class probabilities (shape: rows × classes). On a 1000-row dataset (800 train, 200 trees), `oob_score_` was **0.885**; taking the argmax of `oob_decision_function_` and computing accuracy by hand gave **0.885** as well. Test accuracy was 0.905.

**Other metrics.** In my installed scikit-learn (1.8.0), `oob_score` also accepts a callable. Passing `mean_squared_error` gave an OOB score of 2014.43, matching `mean_squared_error(y_train, rf.oob_prediction_)` exactly. (Check the documentation for your installed version, since this option appeared in later releases.)

## 📓 The Notebook Cell

```python
from sklearn.ensemble import RandomForestRegressor
from sklearn.metrics import r2_score

# 1. Random Forest with OOB evaluation
rf_oob = RandomForestRegressor(
    n_estimators=100,
    bootstrap=True,
    oob_score=True,
    random_state=42,
    n_jobs=-1,
)

# 2. Train
rf_oob.fit(X_train, y_train)

# 3. Internal OOB evaluation
print("OOB R²:", rf_oob.oob_score_)

# 4. Final held-out test evaluation
y_pred = rf_oob.predict(X_test)
print("Test R²:", r2_score(y_test, y_pred))

# 5. Manual verification of the OOB score
print("Manual OOB R²:", r2_score(y_train, rf_oob.oob_prediction_))

# 6. Peek at the row-level OOB predictions
print(len(rf_oob.oob_prediction_), len(y_train))
print(rf_oob.oob_prediction_[:10])
```

Your actual values depend on your dataset, split, parameters and seed.

## 🌀 Deepest Realization

OOB works because bootstrap sampling quietly creates something for free: for every row, a group of trees that has never met it. Asking only those trees turns the training set into its own test set, one row at a time.

```
Row by row:   eligible trees predict → aggregate → one OOB prediction per row
Overall:      compare all OOB predictions with actual values → one score
```

That is why you never supply a row number: OOB evaluation is an **entire-training-set** mechanism, not a single-row prediction function.

## ✅ Final Takeaway

> **"Every training row has a group of trees that never saw it. Random Forest asks only those trees to predict it and averages their answers, producing one OOB prediction per row. Then it compares all those predictions with the true values and reports one score: R² for regression, accuracy for classification. That is `oob_score_`, a free internal estimate of how the forest will do on unseen data."**
