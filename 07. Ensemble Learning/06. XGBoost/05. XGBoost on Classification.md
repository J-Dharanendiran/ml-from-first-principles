# 🎯 The Correction That Lived in Log-Odds: XGBoost Classification, Explained

> *"A classifier built by boosting never corrects a probability directly. It corrects a score, and the probability is only what the score looks like through a sigmoid."*

You have already seen XGBoost predict a number: mean → residuals → trees that learn corrections. Now the target is not a package but a **yes/no**: placed or not placed.

Does the whole machine change? Mostly no. The skeleton is the same. What changes is **where the corrections live** and **what the denominator of the Similarity Score becomes**. This chapter walks through both, with every number recomputed.

> ⚠️ **A warning about the source.** The transcript behind this chapter is an automatic Hindi-to-text transcription, and the source itself says several decimals are garbled. I kept the teacher's method and formulas, and **recomputed every number** (and cross-checked with real XGBoost). Where the transcript's numbers cannot be reproduced, this chapter says so and uses the recomputed ones. The notes at the end list exactly which.

---

## 📋 The Problem

A tiny placement dataset with one feature:

| CGPA | Placement |
|-----:|----------:|
| 5.70 | 0 |
| 6.24 | 0 |
| 7.10 | 0 |
| 8.15 | 1 |
| 9.60 | 1 |

`0 = not placed`, `1 = placed`.

**Goal:** given a student's CGPA, predict whether they get placed. That makes this **binary classification**.

---

## 🧭 The Big Picture: Same Boosting Philosophy

> **XGBoost is essentially Gradient Boosting with additional optimizations.**

The workflow you already know:

```
Start with a base model
        ↓
Calculate errors
        ↓
Train a small tree to correct those errors
        ↓
Add the tree to the existing model
        ↓
Calculate new errors
        ↓
Train another tree
        ↓
Repeat
```

This is **stage-wise additive modeling**: each new model improves on what the previous collection got wrong.

The difference the lecture emphasises: XGBoost builds its trees using a special score, the **Similarity Score**.

> 🔎 **A small correction to how the lecture frames this.** The lecture contrasts the Similarity Score with "Gini or entropy". But ordinary Gradient Boosting classification does *not* use Gini or entropy for its trees. I checked scikit-learn's `GradientBoostingClassifier` and its trees are `DecisionTreeRegressor` trees using the `friedman_mse` criterion, fitted to the residuals. So the real contrast is **XGBoost's Similarity Score and Gain versus the regression-tree criterion used on residuals in classic Gradient Boosting**. (Gini and entropy belong to a standalone classification decision tree.)

---

## 1️⃣ Why Can't We Start With the Mean?

> 💭 *"In regression we started with the mean. Why not here?"*

In regression the targets are numbers like `10, 20, 30, 40`, and the mean (25) is a sensible first guess.

Here the targets are `0, 0, 0, 1, 1`. The mean is $\frac{0+0+0+1+1}{5} = 0.6$, which looks fine as a probability. The catch is that the model is **not meant to add its corrections in probability space**. If trees added corrections directly to a probability, you could end up with 1.3 or −0.2, which are not probabilities.

So XGBoost classification starts in **log-odds space**, where a score can be any real number, and converts to probability only at the end.

---

## 2️⃣ Step One: The Starting Probability

Three of the five students were placed:

$$p = \frac{3}{5} = 0.6$$

The first model effectively says: *"I know nothing about CGPA yet, so everyone gets a 60% chance of placement."* Useless as a classifier, perfect as a starting point.

### Convert it to log-odds

$$\text{log-odds} = \ln\!\left(\frac{p}{1-p}\right) = \ln\!\left(\frac{0.6}{0.4}\right) = \ln(1.5) \approx 0.405$$

$$F_0(x) = 0.405 \quad \text{for every student}$$

```
CGPA = 5.70  → 0.405
CGPA = 6.24  → 0.405
CGPA = 7.10  → 0.405
CGPA = 8.15  → 0.405
CGPA = 9.60  → 0.405
```

The model ignores CGPA completely, for now.

### 🔁 But 0.405 is not a probability

> 💭 *"So how do I read this number?"*

Convert back with the logistic (sigmoid) function:

$$p = \frac{e^{F(x)}}{1 + e^{F(x)}} \qquad \Rightarrow \qquad \frac{e^{0.405}}{1+e^{0.405}} = 0.60$$

```
log-odds → probability → class
0.405    → 0.60        → 0.60 > 0.5 → class 1
```

---

## 3️⃣ Step Two: Measure the Errors

The model predicts $p = 0.6$ for everyone. The classification residual is:

$$r_i = y_i - p_i$$

| Actual $y$ | Prediction $p$ | Residual |
|---:|---:|---:|
| 0 | 0.6 | −0.6 |
| 0 | 0.6 | −0.6 |
| 0 | 0.6 | −0.6 |
| 1 | 0.6 | +0.4 |
| 1 | 0.6 | +0.4 |

These are the **pseudo-residuals**. The next tree will try to learn them.

---

## 4️⃣ What Does the Next Tree Actually Learn?

Not `Placement = 0 or 1`. The **residual**.

| CGPA | Residual |
|-----:|---------:|
| 5.70 | −0.6 |
| 6.24 | −0.6 |
| 7.10 | −0.6 |
| 8.15 | +0.4 |
| 9.60 | +0.4 |

> 💭 *"Can I divide CGPA into groups where the residuals are similar?"*

That is the entire job of the tree.

### ✂️ Where can it split?

Sort the CGPAs and take midpoints of neighbours:

$$\tfrac{5.70+6.24}{2} = 5.97 \qquad \tfrac{6.24+7.10}{2} = 6.67 \qquad \tfrac{7.10+8.15}{2} = 7.625 \qquad \tfrac{8.15+9.60}{2} = 8.875$$

*(The lecture writes the third one as 7.62, truncated. The exact midpoint is 7.625.)*

---

## 5️⃣ The Similarity Score, Classification Edition

Start with all residuals in one leaf: `[−0.6, −0.6, −0.6, +0.4, +0.4]`. The lecture's formula:

$$\boxed{SS = \frac{\left(\sum r_i\right)^2}{\sum p_i(1-p_i) + \lambda}}$$

with $\lambda = 0$ for this example.

Compare it with the regression version you learned earlier:

| | Denominator |
|---|---|
| Regression | $N + \lambda$ (the *count* of residuals) |
| Classification | $\sum p_i(1-p_i) + \lambda$ |

> 💭 *"Why did the denominator change from a count to $p(1-p)$?"*

The lecture treats the formula as given and postpones the derivation. Here is where it comes from, in short; the full story is for the math lecture.

1. XGBoost scores a leaf using the **gradient** $g$ and **Hessian** $h$ of the loss with respect to the current score $F$.
2. For **squared error**: $g = F - y$ (minus the residual) and $h = 1$. Summing $h$ over a leaf gives $N$.
3. For **log-loss with $p = \sigma(F)$**: $g = p - y$ (again minus the residual) and $h = p(1-p)$.
4. The leaf formulas $\frac{G^2}{H+\lambda}$ and $\frac{-G}{H+\lambda}$ then become exactly the lecture's formulas: $G = -\sum r_i$ and $H = \sum p_i(1-p_i)$.

So the denominator did not change by accident. **It is the Hessian of the loss.** For regression it counts samples; for classification it counts samples *weighted by how uncertain each prediction already is*. A sample the model is nearly sure about ($p$ close to 0 or 1) has $p(1-p) \approx 0$ and contributes little; a 50/50 sample contributes the most.

### 🔍 Why the score rewards agreement

Residuals pointing the same way reinforce; opposing ones cancel:

```
Leaf of  −0.6, −0.6, −0.6  → sum −1.8 → strong, consistent correction
Leaf of  −0.6, +0.4        → sum −0.2 → weak, they partly cancel
```

A good split puts residuals that agree in direction into the same leaf.

---

## 6️⃣ Test Every Split

Here every sample has $p = 0.6$, so each has $p(1-p) = 0.24$.

**Root:** sum of residuals $= -1.8 + 0.8 = -1.0$; Hessian sum $= 5 \times 0.24 = 1.2$

$$SS_{\text{root}} = \frac{(-1.0)^2}{1.2} = 0.8333$$

$$\text{Gain} = SS_L + SS_R - SS_{\text{root}}$$

| Split | Left residuals | $SS_L$ | Right residuals | $SS_R$ | Gain |
|---|---|---:|---|---:|---:|
| CGPA < 5.97 | −0.6 | 1.5000 | −0.6, −0.6, +0.4, +0.4 | 0.1667 | 0.8333 |
| CGPA < 6.67 | −0.6, −0.6 | 3.0000 | −0.6, +0.4, +0.4 | 0.0556 | 2.2222 |
| **CGPA < 7.625** | −0.6, −0.6, −0.6 | 4.5000 | +0.4, +0.4 | 1.3333 | **5.0000** |
| CGPA < 8.875 | −0.6, −0.6, −0.6, +0.4 | 2.0417 | +0.4 | 0.6667 | 1.8750 |

Worked example for the winner: left sum $= -1.8$, Hessian $= 3 \times 0.24 = 0.72$, so $SS_L = \frac{3.24}{0.72} = 4.5$. Right sum $= +0.8$, Hessian $= 0.48$, so $SS_R = \frac{0.64}{0.48} = 1.3333$. Gain $= 4.5 + 1.3333 - 0.8333 = 5.0$.

```
            CGPA < 7.625 ?
                  │
          ┌───────┴───────┐
          ↓               ↓
        LEFT            RIGHT
       5.70             8.15
       6.24             9.60
       7.10
   (−0.6, −0.6, −0.6)  (+0.4, +0.4)
```

Look at what happened: the left side collected the negative corrections, the right side the positive ones.

### 🧠 The question you were carrying

> 💭 *"How does XGBoost put positive corrections on one side and negative corrections on the other?"*

It doesn't, as a rule. Step by step:

1. It has `CGPA` and `Residual` for each row.
2. It tries a possible CGPA threshold.
3. It computes the Similarity Scores of the resulting leaves.
4. It repeats for every possible threshold.
5. It keeps the split with the **best Gain**.

The positive/negative separation is an **emergent result of maximising the score**. The algorithm never "understood" that high CGPA tends to mean placement. It only found that this cut produces leaves with stronger, more consistent correction signals.

---

## 7️⃣ What Does Each Leaf Say?

$$\boxed{\text{Output} = \frac{\sum r_i}{\sum p_i(1-p_i) + \lambda}}$$

Notice the family resemblance:

```
Similarity Score → numerator is squared
Leaf Output      → numerator is NOT squared
```

For our split:

$$\text{Left} = \frac{-1.8}{0.72} = \boxed{-2.5} \qquad \text{Right} = \frac{+0.8}{0.48} = \boxed{+1.667}$$

```
             CGPA < 7.625 ?
                 /       \
               Yes        No
                │          │
              −2.5       +1.667
```

> ⚠️ **Where I disagree with the transcript.** It reports the leaf outputs as **−1.11** and **+1.66**. The right leaf matches my +1.667. The left leaf does **not**: the formula, with the lecture's own residuals, gives −2.5, and I could not reproduce −1.11 from any consistent reading of the data. I treat −1.11 as a transcription or arithmetic slip and use **−2.5**.

These leaf values are **not final predictions**. They are corrections **in log-odds space**.

---

## 8️⃣ Add the Tree, Gently

Combine the base model and the tree, scaled by the learning rate $\eta$ (the lecture uses $0.3$):

$$F_1(x) = F_0 + \eta\, M_2(x)$$

### 👩‍🎓 A low-CGPA student (5.70)

$5.70 < 7.625$, so the student goes to the left leaf:

$$F_1 = 0.405 + 0.3(-2.5) = 0.405 - 0.75 = -0.345$$

Convert to probability:

$$p = \frac{e^{-0.345}}{1 + e^{-0.345}} \approx \boxed{0.415}$$

The probability moved **down** from 0.60.

### 🎓 A high-CGPA student (8.15)

$8.15 > 7.625$, so the student goes to the right leaf:

$$F_1 = 0.405 + 0.3(1.667) = 0.405 + 0.5 = 0.905$$

$$p = \frac{e^{0.905}}{1 + e^{0.905}} \approx \boxed{0.712}$$

The probability moved **up**. (The transcript's 0.712 for this student matches. Its 0.518 for the low-CGPA student was built on the −1.11 leaf, which is why it differs from my 0.415.)

```
              Initial model          After Tree 1
5.70   ───────→  60%     ───────→     41.5%
6.24   ───────→  60%     ───────→     41.5%
7.10   ───────→  60%     ───────→     41.5%
8.15   ───────→  60%     ───────→     71.2%
9.60   ───────→  60%     ───────→     71.2%
```

The model now actually uses the feature.

### 🔬 Reading the learning rate

The tree says "correct by $+1.667$", and with $\eta = 0.3$ only $0.3 \times 1.667 = 0.5$ is added.

> The tree is saying: *"I think the correction should be this big, but let's only move 30% of the way there."*

Many small steps instead of a few large ones is gradual learning.

## 9️⃣ New Residuals: The Loop Closes

Compare the actual value with the **new probability**:

| Student | Actual | New $p$ | Old residual | New residual |
|---|---:|---:|---:|---:|
| 5.70 | 0 | 0.4147 | −0.6 | **−0.4147** |
| 6.24 | 0 | 0.4147 | −0.6 | **−0.4147** |
| 7.10 | 0 | 0.4147 | −0.6 | **−0.4147** |
| 8.15 | 1 | 0.7121 | +0.4 | **+0.2879** |
| 9.60 | 1 | 0.7121 | +0.4 | **+0.2879** |

Every residual moved toward zero, which is the proof that Tree 1 helped.

## 🔟 Model Three, and Why You Never Start Over

> 💭 *"Do we throw everything away and start again?"*

No. We **keep the entire model built so far**, compute new residuals, and train the next tree on those:

$$F_1(x) = F_0 + \eta M_2(x) \qquad\Rightarrow\qquad F_2(x) = F_0 + \eta M_2(x) + \eta M_3(x)$$

This round the Hessians are no longer all 0.24, because the probabilities changed: $p(1-p) = 0.2427$ for the first three students and $0.2050$ for the last two. Searching the same four thresholds again:

| Split | Left residuals | Right residuals | Gain |
|---|---|---|---:|
| CGPA < 5.97 | −0.4147 | rest | 0.3880 |
| CGPA < 6.67 | −0.4147, −0.4147 | rest | 1.0645 |
| **CGPA < 7.625** | −0.4147 ×3 | +0.2879 ×2 | **2.5420** |
| CGPA < 8.875 | −0.4147 ×3, +0.2879 | +0.2879 | 0.9918 |

Leaf outputs: $-1.7085$ (left) and $+1.4044$ (right). The same CGPA threshold wins again here, because with one feature and one clean boundary it is still the most useful question. With more features, a different one could win.

Adding $\eta = 0.3$ of each:

| Student | Log-odds after 2 trees | Probability |
|---|---:|---:|
| 5.70, 6.24, 7.10 | −0.857 | **0.298** |
| 8.15, 9.60 | +1.327 | **0.790** |

The low group's probability fell from 0.415 to 0.298, and the high group rose from 0.712 to 0.790. Each tree sharpens the separation.

Then Model 4 does the same, and so on:

$$F(x) = F_0 + \eta M_2(x) + \eta M_3(x) + \eta M_4(x) + \cdots$$

## 1️⃣1️⃣ A Brand-New Student Walks In

> 💭 *"Does a new sample pass through all the trees?"*

Yes. Suppose the new student has $\text{CGPA} = 7.8$ and nobody knows their placement.

1. **Start** with the base log-odds: $F_0 = 0.405$.
2. **Tree 1:** $7.8 > 7.625$ → right leaf (+1.667) → add $0.3 \times 1.667 = 0.5$ → $F = 0.905$.
3. **Tree 2:** $7.8 > 7.625$ → right leaf (+1.4044) → add $0.3 \times 1.4044 = 0.4213$ → $F = 1.3268$.
4. **Continue** through every remaining tree.
5. **Convert** the final log-odds to a probability.
6. **Apply the threshold** (e.g. $p \ge 0.5 \Rightarrow 1$).

With our two trees:

$$p = \frac{e^{1.3268}}{1 + e^{1.3268}} \approx \boxed{0.790} \;\Rightarrow\; \text{class } 1$$

Nothing is retrained. The student simply travels through every tree, collecting corrections, and the sum is turned into a probability once, at the end.

## 🧠 The Mental Pictures

### The correction specialists

- **Model 1:** *"I'll make a rough starting prediction."*
- **Model 2:** *"Here are the biggest mistakes. I'll correct those."*
- **Model 3:** *"After Model 2, these mistakes remain. I'll correct those."*
- **Model 4:** *"These errors remain now. I'll correct those."*

$$\boxed{\text{Initial prediction} + \text{small correction} + \text{small correction} + \cdots}$$

### What is the tree really learning?

Not `CGPA → Placement`, but:

> **CGPA → "How should I modify the current prediction?"**

```
CGPA < 7.625 → negative correction
CGPA ≥ 7.625 → positive correction
```

### Why not ordinary tree rules?

A standalone classification tree asks *"which split makes the labels purest?"* XGBoost asks *"which split gives the most useful corrections to the current model?"*, and answers it with the Similarity Score and Gain:

$$\text{Gain} = SS_L + SS_R - SS_{\text{root}}$$

### When does it stop?

The lecture says to continue until residuals are zero or very close to it, or until you reach the chosen number of stages. In real XGBoost, stopping is also controlled by tree depth, regularization, the number of estimators, the learning rate, and validation criteria; those are beyond this lecture.

---

## 📌 The Seven Steps of the Lecture

1. **Base model:** starting probability = positive ratio → log-odds $F_0$.
2. **Residuals:** $r_i = y_i - p_i$.
3. **Build a tree** on the residuals: try every split, score with

$$SS = \frac{(\sum r_i)^2}{\sum p_i(1-p_i) + \lambda}$$

4. **Gain:** $SS_L + SS_R - SS_{\text{root}}$; keep the best split.
5. **Leaf output:** $\dfrac{\sum r_i}{\sum p_i(1-p_i) + \lambda}$.
6. **Update:** $F_{\text{new}} = F_{\text{old}} + \eta \times \text{Tree}(x)$.
7. **Convert** log-odds to probability, compute new residuals, repeat.

### The equations that tie it together

$$\boxed{F_m(x) = F_{m-1}(x) + \eta\, f_m(x)} \qquad \boxed{p(x) = \frac{e^{F_m(x)}}{1 + e^{F_m(x)}}} \qquad \boxed{r_i = y_i - p_i}$$

```
Predict → Find error → Build correction tree → Add correction → Repeat
```

### The full diagram

```
              Training Dataset
                     │
        p = positive ratio → log-odds
                     │
               Base Model F₀
                     │
             Calculate residuals
                     │
          ┌──────────┴──────────┐
   Try possible splits     Calculate Gain
          └──────────┬──────────┘
                Best split
                     │
            Calculate leaf output
                     │
           × learning rate, add to model
                     │
          Convert to probability
                     │
               New residuals
                     │
           Build next tree → Repeat
                     │
              Final XGBoost Model
```

### Three families side by side

```
Random Forest          Gradient Boosting        XGBoost
Many independent       Tree 1 → errors →        Base prediction → tree
trees → combine        Tree 2 → errors →        correcting errors → tree
                       Tree 3                   correcting remaining errors…
                                                + gradient-based optimisation,
                                                regularization, engineering
```

## 🛠️ One Practical Surprise: Real XGBoost Might Refuse to Split

If you copy this tiny dataset into a real `XGBClassifier` with `max_depth=1`, `learning_rate=0.3`, `reg_lambda=0` and `base_score=0.6`, **using the default settings otherwise, it builds a tree with no split at all.**

Why? The default `min_child_weight` is 1, and it is compared against the **sum of Hessians** in each child. Our children have Hessian sums of $0.72$ and $0.48$, both below 1, so the split is rejected. Setting `min_child_weight=0` makes real XGBoost reproduce this chapter exactly: root split at 7.625 with gain 5.0, and probabilities of 0.4147 and 0.7121 after one tree.

This is the Hessian from section 5 showing up in a real hyperparameter: for classification, `min_child_weight` is about **total uncertainty-weighted mass in a leaf**, not the number of samples.

## 🌉 ML Bridge

- **Classification and regression share one engine.** The tree machinery is identical. Only $g$ and $h$ change: $(F-y,\ 1)$ for squared error, $(p-y,\ p(1-p))$ for log-loss.
- **Log-odds is the working space; probability is the display.** This is the same reason logistic regression is linear in log-odds. Trees add corrections to a score, never to a probability.
- **Hyperparameters read differently once you know the Hessian.** `min_child_weight` and $\lambda$ both live in the same denominator as $\sum p(1-p)$.
- **Confident samples matter less.** A sample with $p$ near 0 or 1 contributes almost no Hessian mass, so later trees focus on the uncertain ones.

---

## 🌀 Deepest Realization

> Residuals say *which direction* each row needs to move, and the Hessian says *how much that row can be trusted to move*. The Similarity Score is just the two combined: a squared push divided by a measure of uncertainty. Regression is the special case where every row's uncertainty is the same.

---

## ✅ Final Takeaway

> *"XGBoost classification starts from a log-odds guess, lets each small tree learn the correction the current model still needs, and turns the running total into a probability only at the end. Same boosting loop as regression, with the denominator upgraded from 'how many rows' to 'how uncertain are they'."*
