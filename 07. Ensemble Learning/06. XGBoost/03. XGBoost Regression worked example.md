# 🧮 The Tree That Chose Its Own Question: XGBoost Regression, Worked by Hand With Two Features

> *"A split is never told which residuals to separate. It is told which feature and threshold to try, and the residuals simply travel with their rows to whichever side they land."*

The previous chapter gave you the flow of XGBoost regression: mean → residuals → trees that learn corrections, scored by a Similarity Score. That chapter used one feature. This one does the thing that makes the machinery feel like arithmetic instead of wizardry: **two features (CGPA and IQ), two trees, one training student followed all the way through, and one brand-new student predicted from scratch.**

> ⚠️ **Scope of this chapter.** This is a deliberately simplified, educational version of XGBoost that follows the lecture's residual / Similarity Score formulation, with $\lambda = 0$, a tiny dataset, and trees of **one split each**. Full XGBoost works with gradients and Hessians, which come later in the mathematical formulation. For squared error and $\lambda = 0$ the two views agree, which is why this simplified version is a fair picture.

---

## 📋 The Dataset

You want to predict a student's package from two features.

| Student | CGPA | IQ | Package (LPA) |
|---------|-----:|---:|--------------:|
| A | 6.0 | 110 | 4 |
| B | 6.5 | 90 | 5 |
| C | 7.0 | 100 | 6 |
| D | 8.0 | 105 | 8 |
| E | 8.5 | 130 | 9 |
| F | 9.0 | 115 | 10 |

```
Features:  CGPA, IQ
Target:    Package

We want:   f(CGPA, IQ) → Package
```

---

## 1️⃣ Stage One: The Mean Ignores Everyone

The first model ignores both features and predicts the mean:

$$\frac{4+5+6+8+9+10}{6} = \frac{42}{6} = \boxed{7}$$

$$\text{Residual} = \text{Actual} - \text{Prediction}$$

| Student | Actual | Prediction | Residual |
|---------|-------:|-----------:|---------:|
| A | 4 | 7 | −3 |
| B | 5 | 7 | −2 |
| C | 6 | 7 | −1 |
| D | 8 | 7 | +1 |
| E | 9 | 7 | +2 |
| F | 10 | 7 | +3 |

So the training data XGBoost sees for Tree 1 is:

```
CGPA    IQ     Residual
6.0     110      -3
6.5      90      -2
7.0     100      -1
8.0     105      +1
8.5     130      +2
9.0     115      +3
```

---

## 2️⃣ What Is Tree 1 Actually Trying to Learn?

Not the package. The **residual**.

> 💭 *"Can I use CGPA and IQ to find groups of students that need similar corrections?"*

That is the whole question Tree 1 asks.

---

## 3️⃣ First Candidate Feature: CGPA

Sort the CGPAs: `6.0, 6.5, 7.0, 8.0, 8.5, 9.0`. The candidate thresholds are the midpoints:

$$6.25,\; 6.75,\; 7.5,\; 8.25,\; 8.75$$

Take one of them, $\text{CGPA} < 7.5$:

```
LEFT              RIGHT
A  −3             D  +1
B  −2             E  +2
C  −1             F  +3
```

Look at what happened. Nobody told XGBoost *"put negative residuals on the left."* It was only handed a question about a feature, $\text{CGPA} < 7.5$, and the residuals came along with their rows.

### 📏 Score it with the Similarity Score

$$SS = \frac{\left(\sum \text{Residual}\right)^2}{N + \lambda}, \qquad \lambda = 0$$

- **Parent** (all six residuals): sum = 0, so $SS_{\text{parent}} = 0$
- **Left** $(-3, -2, -1)$: sum = −6, so $SS_L = \dfrac{36}{3} = \boxed{12}$
- **Right** $(+1, +2, +3)$: sum = +6, so $SS_R = \dfrac{36}{3} = \boxed{12}$

$$\text{Gain} = SS_L + SS_R - SS_{\text{parent}} = 12 + 12 - 0 = \boxed{24}$$

A very good split. But XGBoost does not stop at the first good-looking one. It tries **all** of them.

### 📊 Every CGPA candidate for Tree 1

| Split | Left residuals | $SS_L$ | Right residuals | $SS_R$ | Gain |
|---|---|---:|---|---:|---:|
| CGPA < 6.25 | −3 | 9.0000 | −2, −1, +1, +2, +3 | 1.8000 | 10.8000 |
| CGPA < 6.75 | −3, −2 | 12.5000 | −1, +1, +2, +3 | 6.2500 | 18.7500 |
| **CGPA < 7.5** | −3, −2, −1 | 12.0000 | +1, +2, +3 | 12.0000 | **24.0000** |
| CGPA < 8.25 | −3, −2, −1, +1 | 6.2500 | +2, +3 | 12.5000 | 18.7500 |
| CGPA < 8.75 | −3, −2, −1, +1, +2 | 1.8000 | +3 | 9.0000 | 10.8000 |

## 4️⃣ Second Candidate Feature: IQ

> 💭 *"Maybe IQ gives me an even better split?"*

Sorted IQ: `90, 100, 105, 110, 115, 130`. Candidate thresholds: `95, 102.5, 107.5, 112.5, 122.5`.

Try $\text{IQ} < 112.5$. Careful here: this is where it is easy to slip, because the rows are **not** in IQ order.

```
LEFT (IQ < 112.5)           RIGHT (IQ ≥ 112.5)
B (IQ  90)   −2             E (IQ 130)  +2
C (IQ 100)   −1             F (IQ 115)  +3
D (IQ 105)   +1
A (IQ 110)   −3
```

- Left sum: $-2 - 1 + 1 - 3 = -5$, so $SS_L = \dfrac{25}{4} = 6.25$
- Right sum: $2 + 3 = 5$, so $SS_R = \dfrac{25}{2} = 12.5$

$$\text{Gain} = 6.25 + 12.5 - 0 = \boxed{18.75}$$

> 📝 **Clarifying a messy moment.** The source for this chapter first wrote "6.25?" as the gain, then corrected itself to 18.75 while working through the sides. **18.75 is correct**; 6.25 is only the *left leaf's* score.

### 📊 Every IQ candidate for Tree 1

| Split | Left residuals | $SS_L$ | Right residuals | $SS_R$ | Gain |
|---|---|---:|---|---:|---:|
| IQ < 95 | −2 | 4.0000 | −3, −1, +1, +2, +3 | 0.8000 | 4.8000 |
| IQ < 102.5 | −2, −1 | 4.5000 | −3, +1, +2, +3 | 2.2500 | 6.7500 |
| IQ < 107.5 | −2, −1, +1 | 1.3333 | −3, +2, +3 | 1.3333 | 2.6667 |
| **IQ < 112.5** | −3, −2, −1, +1 | 6.2500 | +2, +3 | 12.5000 | **18.7500** |
| IQ < 122.5 | −3, −2, −1, +1, +3 | 0.8000 | +2 | 4.0000 | 4.8000 |

## 5️⃣ The Duel: Which Feature Wins the Root?

| Feature | Best threshold | Gain |
|---|---:|---:|
| CGPA | 7.5 | **24** |
| IQ | 112.5 | 18.75 |

$$\boxed{\text{Root split: CGPA} < 7.5}$$

> 💭 *"How does XGBoost put the positive corrections on one side and the negative corrections on the other?"*

It doesn't. Here is the exact answer, step by step:

1. **Features determine the possible splits**, e.g. $\text{CGPA} < 7.5$ or $\text{IQ} < 112.5$.
2. **A split separates complete rows.**
3. **The residuals come along with their rows.**
4. **The Similarity Score measures how useful the resulting groups are.**
5. **Gain tells XGBoost whether this split beats the alternatives.**
6. **The best split becomes part of the tree.**

$$\boxed{\text{Features determine the split.}} \qquad \boxed{\text{Residuals determine how good the split is.}}$$

The fact that negative corrections mostly land on one side here is a **consequence of how CGPA relates to package**, not something imposed on the tree.

---

## 6️⃣ Tree 1 Takes Shape

```
            CGPA < 7.5 ?
             /        \
          YES          NO
           ↓            ↓
     −3, −2, −1     +1, +2, +3
```

Leaf output (with $\lambda = 0$) is the average residual:

$$\text{Left} = \frac{-3-2-1}{3} = \boxed{-2} \qquad \text{Right} = \frac{1+2+3}{3} = \boxed{+2}$$

```
            CGPA < 7.5 ?
             /        \
          YES          NO
           ↓            ↓
          −2           +2
```

> ⚠️ These are **corrections**, not package predictions.

---

## 7️⃣ Adding the Correction, Gently

Use a learning rate $\eta = 0.5$:

$$\text{New Prediction} = \text{Old Prediction} + 0.5 \times \text{Tree Output}$$

- CGPA < 7.5: $7 + 0.5(-2) = \boxed{6}$
- CGPA ≥ 7.5: $7 + 0.5(+2) = \boxed{8}$

| Student | Actual | Tree 1 prediction |
|---------|-------:|------------------:|
| A | 4 | 6 |
| B | 5 | 6 |
| C | 6 | 6 |
| D | 8 | 8 |
| E | 9 | 8 |
| F | 10 | 8 |

Already far better than "7 for everyone". Now measure what is still wrong:

$$\text{New Residual} = \text{Actual} - \text{New Prediction}$$

| Student | Actual | Prediction | New Residual |
|---------|-------:|-----------:|-------------:|
| A | 4 | 6 | −2 |
| B | 5 | 6 | −1 |
| C | 6 | 6 | 0 |
| D | 8 | 8 | 0 |
| E | 9 | 8 | +1 |
| F | 10 | 8 | +2 |

## 8️⃣ Tree 2 Asks the Same Question Again

```
CGPA    IQ    New Residual
6.0     110      −2
6.5      90      −1
7.0     100       0
8.0     105       0
8.5     130      +1
9.0     115      +2
```

The target is now the **new residual**. And Tree 2 is not obliged to reuse CGPA: it can use CGPA **or** IQ, whichever scores better.

| **CGPA < 6.75** | −2, −1 | 4.5000 | 0, 0, +1, +2 | 2.2500 | **6.7500** |
| CGPA < 7.5 | −2, −1, 0 | 3.0000 | 0, +1, +2 | 3.0000 | 6.0000 |
| **CGPA < 8.25** | −2, −1, 0, 0 | 2.2500 | +1, +2 | 4.5000 | **6.7500** |
| CGPA < 8.75 | −2, −1, 0, 0, +1 | 0.8000 | +2 | 4.0000 | 4.8000 |
| IQ < 95 | −1 | 1.0000 | −2, 0, 0, +1, +2 | 0.2000 | 1.2000 |
| IQ < 102.5 | −1, 0 | 0.5000 | −2, 0, +1, +2 | 0.2500 | 0.7500 |
| IQ < 107.5 | −1, 0, 0 | 0.3333 | −2, +1, +2 | 0.3333 | 0.6667 |
| **IQ < 112.5** | −2, −1, 0, 0 | 2.2500 | +1, +2 | 4.5000 | **6.7500** |

Read the bold rows twice. The source picks $\text{IQ} < 112.5$ and calls it "one of the best available splits", which is true, but there is something the story needs to confess:

> 🤝 **Three splits tie at Gain = 6.75:** $\text{CGPA} < 6.75$, $\text{CGPA} < 8.25$, and $\text{IQ} < 112.5$.

We will come back to what that tie means. First, build the tree the source builds.

### Tree 2 (using the IQ split)

$$\text{IQ} < 112.5: \quad \text{Left } (-2, -1, 0, 0): \frac{-3}{4} = \boxed{-0.75} \qquad \text{Right } (+1, +2): \frac{3}{2} = \boxed{+1.5}$$

```
            IQ < 112.5 ?
             /        \
          YES          NO
           ↓            ↓
        −0.75         +1.5
```

## 9️⃣ Follow One Training Student: A

```
CGPA = 6.0     IQ = 110     Actual package = 4
```

| Step | What happens | Prediction |
|---|---|---:|
| Base model | everyone gets the mean | **7** |
| Residual | $4 - 7$ | −3 |
| Tree 1 | $6.0 < 7.5$ → YES → output −2; $0.5 \times (-2) = -1$ | $7 - 1 = $ **6** |
| New residual | $4 - 6$ | −2 |
| Tree 2 | $110 < 112.5$ → YES → output −0.75; $0.5 \times (-0.75) = -0.375$ | $6 - 0.375 = $ **5.625** |
| Final residual | $4 - 5.625$ | −1.625 |

Still not perfect, but each tree is moving A in the right direction, and another tree could keep correcting what remains.

## 🔟 Now a Student Nobody Has Seen

> 💭 *"A new student walks in. We do not know their package. That is the whole reason we have the model. What happens?"*

```
New student:  CGPA = 7.2     IQ = 118
```

**Base:** 7.

**Tree 1:** $7.2 < 7.5$? TRUE → left leaf, output −2 → $0.5(-2) = -1$ → prediction $7 - 1 = \boxed{6}$.

**Tree 2:** $118 < 112.5$? FALSE → right leaf, output +1.5 → $0.5(1.5) = 0.75$ → prediction $6 + 0.75 = \boxed{6.75}$.

```
                 NEW STUDENT
               CGPA=7.2, IQ=118
                      │
                 Base = 7.0
                      │
          Tree 1: CGPA < 7.5 ?  → YES
                      │
               correction −2 × 0.5 = −1
                      │
                 prediction 6
                      │
          Tree 2: IQ < 112.5 ?  → NO
                      │
              correction +1.5 × 0.5 = +0.75
                      │
                 FINAL = 6.75
```

Nobody retrained anything. The new student simply walked **through every tree in order**, collecting corrections.

---

## 🔥 The Insight, and the Correction

The source says: Tree 1 used CGPA, Tree 2 used IQ, and that is "one of the beautiful things about boosting":

> *"Given what the previous trees have already learned, what information can I use to correct the remaining errors?"*

That question **is** the right way to think about each tree. The model is not saying "CGPA is the important feature, so I'll use CGPA forever." Each tree re-searches **all** features against the **current** residuals.

But one explanation in the source does not survive checking. It says Tree 2 chose IQ because *"the remaining errors had a different structure."* The table in section 8 shows otherwise: **CGPA splits reach exactly the same gain** (6.75), so IQ was not clearly more useful. When gains tie, which split is built depends on how the implementation breaks ties, not on any deeper structure in the data.

### 🧪 Why this is not a harmless detail

Same data, same learning rate, three equally "best" Tree 2 splits:

| Tree 2 split | Left output | Right output | Student A | New student (7.2, 118) |
|---|---:|---:|---:|---:|
| IQ < 112.5 | −0.75 | +1.5 | 5.625 | **6.75** |
| CGPA < 6.75 | −1.5 | +0.75 | 5.25 | **6.375** |
| CGPA < 8.25 | −0.75 | +1.5 | 5.625 | **5.625** |

All three have the same training gain, yet the **new student's prediction ranges from 5.625 to 6.75**. Ties in gain mean the training data cannot tell these trees apart, but new data can.

When I trained a real XGBoost regressor on this data (one split per tree), it chose $\text{CGPA} < 8.25$ for Tree 2, giving **5.625** for the new student, not 6.75. When I swapped the order of the two feature columns, it chose $\text{IQ} < 112.5$ and gave 6.75. So in my runs the tie-break followed column order. I cannot confirm the library's internal tie-breaking rule from this experiment alone.

> The lesson for you: the **6.75** in the walkthrough is a correct answer *for the IQ-split version of Tree 2*. It is not "the" answer XGBoost must give.

## 🧠 The Whole Training Loop, Compressed

```
                 TRAINING DATA
                       │
              Mean Package = 7
                       │
              Calculate residuals
                       │
        ┌──────────────┴──────────────┐
      CGPA                            IQ
   try every split              try every split
        └──────────────┬──────────────┘
                 Calculate Gain
                       │
                Pick the best split
                       │
                  Build Tree 1
                       │
          Predictions → NEW residuals
                       │
        ┌──────────────┴──────────────┐
      CGPA                            IQ
   try every split              try every split
        └──────────────┬──────────────┘
                Pick the best split
                       │
                  Build Tree 2
                       │
                  Tree 3 … Tree N
                       │
              FINAL XGBOOST MODEL
```

$$\boxed{\text{Final Prediction} = \text{Base} + \eta T_1 + \eta T_2 + \eta T_3 + \cdots}$$

## 🌉 ML Bridge

Three habits from this chapter carry into real XGBoost work:

- **Every tree competes across all features.** The root of Tree 1 and the split of Tree 2 were chosen by comparing gains across CGPA *and* IQ. That is why boosted trees handle many features without you choosing which matters.
- **Residuals change, so the best feature can change.** Each tree sees the errors the earlier trees left behind.
- **Ties and near-ties happen with small data.** On large, noisy data exact ties are rare, but on tiny hand-built examples they are common, so do not read too much into *which* of several equally good splits was chosen.

Also note what this chapter simplified: trees had one split each. With more depth, Tree 1 would continue splitting its two groups. A real depth-2 run on this data splits further (the left group of Tree 1 divides at CGPA < 6.75, the right at CGPA < 8.75), so its predictions differ from the table above.

---

## 🌀 Deepest Realization

> A feature never says "negative corrections go here." A **question** about a feature moves whole rows, and the **residuals** decide whether that question was worth asking. The tree is a record of the questions that paid off.

---

## ✅ Final Takeaway

> *"Features propose the splits, residuals judge them, and every new tree asks again: given everything the earlier trees have already corrected, what is still wrong, and which question about the data fixes it best?"*
