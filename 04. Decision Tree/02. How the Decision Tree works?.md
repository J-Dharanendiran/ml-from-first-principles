# 🌡️ The Number That Measures How Mixed You Are

> *"You cannot tell a computer to 'look at the data and pick the feature that looks good.' You have to give it a number."*

---

You left the last chapter with a tree that knows *how* to grow — root, split, decision node, leaf, repeat — but not *why* it picks one feature over another. Every step of that recursive build depends on a single unanswered question:

> **How does the algorithm know which feature is "best"?**

Humans can eyeball a dataset and feel out a good split. Computers can't. So before the tree can choose anything, it needs a number that tells it exactly **how impure or uncertain the data is at this node.** That number is **Entropy**.

## 🎲 The Core Intuition, Before Any Math

Entropy measures **impurity, randomness, disorder, uncertainty** — four words for the same thing. And the relationship is simple:

> **More uncertainty → higher Entropy.**
> **Less uncertainty → lower Entropy.**

The more you already know about a system, the less uncertain it is, and the lower its Entropy.

## 🟢🔴 Two Nodes, Two Extremes

Picture a node holding 10 points.

**Case 1 — all one class:**
```
Yes Yes Yes Yes Yes
Yes Yes Yes Yes Yes
```
Ask "what class will the next point belong to?" and the answer is obvious every time. Zero uncertainty.
```
Entropy = 0
```
This is a **completely pure node**.

**Case 2 — classes mixed together:**
```
Yes No Yes No No
No Yes No Yes No
```
Now the same question has no confident answer.
```
Entropy = High
```

So:

```
Pure data → Low uncertainty → Low Entropy
Mixed data → High uncertainty → High Entropy
```

> *"Is there a physical-world version of this I can hold onto?"*

Think of water's states — solid, liquid, vapour. The less predictable the state, the greater the disorder. Same intuition, different substance: **Entropy rises with unpredictability**, whether you're talking molecules or class labels.

## 📊 Entropy in an Actual Dataset

Two classes, `A` and `B`.

**Dataset 1** — everything is `A`:
```
A A A A A A A A A A
```
$$P(A) = 1, \quad P(B) = 0 \quad\Rightarrow\quad Entropy = 0$$

**Dataset 2** — perfectly split:
```
A A A A A B B B B B
```
$$P(A) = 0.5, \quad P(B) = 0.5 \quad\Rightarrow\quad Entropy = \text{Maximum} = 1$$

The pure case sits at the minimum. The perfectly mixed case sits at the maximum. Everything else lives somewhere in between.

---

## 🧮 Turning the Intuition Into a Formula

For binary classification, with $P_+$ and $P_-$ as the proportions of each class:

$$
\boxed{Entropy(X) = -P_+\log_2(P_+) - P_-\log_2(P_-)}
$$

Let's actually run the numbers for the 50/50 case, step by step, instead of just trusting the label "maximum."

$$
Entropy = -(0.5)\log_2(0.5) - (0.5)\log_2(0.5)
$$

Since $\log_2(0.5) = -1$:

$$
Entropy = -(0.5)(-1) - (0.5)(-1) = 0.5 + 0.5
$$

$$
\boxed{Entropy = 1}
$$

A perfectly balanced binary node hits the ceiling.

## 🕳️ Why Pure Data Hits Exactly Zero

Set $P_+ = 1$ and $P_- = 0$:

$$
Entropy = -(1)\log_2(1) - (0)\log_2(0)
$$

$\log_2(1) = 0$, so the first term vanishes entirely. The second term — $0 \cdot \log_2(0)$ — approaches zero as well (this is the standard convention: $0\log_2 0 \equiv 0$, since a class with zero probability contributes zero uncertainty).

$$
\boxed{Entropy = 0}
$$

No uncertainty, because the node only ever contains one class. There's genuinely nothing left to ask.

## 📈 The Full Curve

Put probability of one class on the x-axis and Entropy on the y-axis:

```
Entropy
  1 |              ●
    |           /     \
    |         /         \
    |       /             \
    |     /                 \
  0 | ●-----------------------●
    +----------------------------→
      0          0.5           1
             P(Class A)
```

| Class distribution | Entropy |
|---|---|
| 100% A / 0% B | 0 |
| 75% A / 25% B | ↓ |
| 50% A / 50% B | **1** |
| 25% A / 75% B | ↓ |
| 0% A / 100% B | 0 |

The curve touches zero at *both* ends and peaks in the middle — Entropy doesn't care which class dominates, only **how mixed the two are.**

## 🔢 Beyond Two Classes

The binary formula is just the special case of a more general rule. With $c$ classes and $P_i$ the proportion of class $i$:

$$
\boxed{Entropy(X) = -\sum_{i=1}^{c} P_i \log_2(P_i)}
$$

For three classes `A`, `B`, `C`, that's simply:

$$
Entropy = -P_A\log_2(P_A) - P_B\log_2(P_B) - P_C\log_2(P_C)
$$

Same logic, one term added per extra class.

## 🧭 Entropy as an Inverse of Knowledge

Here's a second lens on the exact same idea. If I tell you *"every point in this node is Class A,"* you now know everything relevant:

```
Knowledge ↑ → Uncertainty ↓ → Entropy ↓
```

If instead I say *"half are A, half are B,"* you know far less about any individual point:

```
Knowledge ↓ → Uncertainty ↑ → Entropy ↑
```

Entropy and knowledge move in opposite directions. Always.

## 🌳 What This Actually Buys the Tree

Recall the recursive build from last chapter — find best feature, split, repeat. Now you can finally define "best":

```
Current Node
     |
     ├── Possible Split 1 → resulting impurity
     ├── Possible Split 2 → resulting impurity
     └── Possible Split 3 → resulting impurity
```

A useful split is one that takes:

```
Before split → High impurity
      ↓
   SPLIT
      ↓
After split → Lower impurity
```

Entropy is the ruler the tree uses to measure that "before" and "after." (How the tree turns *that* comparison into a concrete score for choosing between splits is Information Gain — the next chapter's job.)

## 🔁 The Second Half: Entropy Is Not Probability

> *"Wait — is Entropy just another name for probability?"*

No, and this distinction matters. **Entropy is calculated *from* a probability distribution — it isn't a probability itself.**

Start with $P(A)$, the proportion of Class A. Since there are only two classes:

$$
P(B) = 1 - P(A)
$$

So Entropy, instead of depending on two separate numbers, collapses into a function of just one:

$$
H(P) = -P\log_2P - (1-P)\log_2(1-P)
$$

Which lets you plot the exact same curve as before, purely as a function of a single probability:

```
Entropy
  1.0 |              ●
      |            /   \
      |          /       \
      |        /           \
      |      /               \
  0.0 | ●---------------------●
      +--------------------------→
        0        0.5           1
             Probability
```

## 🔄 Why the Curve Is Symmetric

Compare two situations:

- **Situation 1:** $P(A) = 0.2 \Rightarrow P(B) = 0.8$
- **Situation 2:** $P(A) = 0.8 \Rightarrow P(B) = 0.2$

The labels have simply been swapped — but the *degree of mixedness* is identical in both. So:

$$
H(0.2) = H(0.8)
$$

```
Entropy
  1 |              ●
    |           /     \
    |         /         \
    |       /             \
    |     /                 \
  0 | ●-----------------------●
    +----------------------------→
      0    .2   .5   .8       1
             P(Class A)
```

Entropy genuinely doesn't care *which* class is in the majority. It only cares how close the split is to 50/50. Probability answers *"how much of each class is present?"* — Entropy converts that answer into *"how uncertain does that distribution make me?"*

```
Class probabilities
       ↓
    Entropy
       ↓
Amount of uncertainty
```

## 🌳 Bringing It Back to a Split

Before splitting, a node might look like:

```
Class A → 50%
Class B → 50%
```
$$Entropy = 1 \quad\text{(highly impure)}$$

Now imagine a split produces two children:

```
Left node:  Class A → 100%, Class B → 0%   → Entropy = 0
Right node: Class A → 0%,   Class B → 100% → Entropy = 0
```

The split took:

```
Mixed data → Pure data
High entropy → Low entropy
```

That transformation — mixed becoming pure, high Entropy collapsing toward zero — is exactly the signature of a *good* split.

| P(Class A) | P(Class B) | Entropy |
|---:|---:|---:|
| 0.0 | 1.0 | 0 |
| 0.1 | 0.9 | Low |
| 0.3 | 0.7 | Higher |
| 0.5 | 0.5 | **Max = 1** |
| 0.7 | 0.3 | Higher |
| 0.9 | 0.1 | Low |
| 1.0 | 0.0 | 0 |

$$
\boxed{\text{Probability becomes balanced} \Rightarrow \text{Entropy increases}}
$$
$$
\boxed{\text{Probability becomes dominated by one class} \Rightarrow \text{Entropy decreases}}
$$

---

## 🩺 Sanity Check

- Entropy is bounded: for binary classification, $0 \leq Entropy \leq 1$.
- It hits **0** at both extremes (100/0 and 0/100) and peaks at **1** exactly at 50/50.
- It is symmetric: $H(P) = H(1-P)$ — Entropy tracks *mixedness*, not *which* class wins.
- It is not a probability; it's a single number *derived from* a probability distribution.

## 🌉 ML Bridge

This is the tree's version of a loss function. Linear and Logistic Regression minimize MSE or cross-entropy over continuous parameters using gradients; a Decision Tree has no parameters to nudge — instead, at every node, it evaluates a *discrete* menu of possible splits and picks whichever one drops Entropy the most. Same underlying goal — reduce a measure of "wrongness" — completely different mechanism for pursuing it.

## 🌀 Deepest Realization

Entropy doesn't ask "which class is correct?" — it refuses to take sides entirely. A node that's 90% Class A and a node that's 90% Class B carry *identical* Entropy, because Entropy was never measuring correctness. It was measuring **how confidently you could guess**, and confidence doesn't care about the label — only about how lopsided the distribution is. That's why the curve is symmetric, and it's the same reason the pure formula and the probability formula turned out to be one and the same idea wearing two notations.

## ✅ Final Takeaway

> *"Entropy converts the intuitive question 'how mixed is this node?' into a single number the tree can use to compare splits — zero when the node is perfectly pure, one when it's perfectly balanced, and derived directly from the class probability distribution rather than being a probability itself."*
