# 🌳 The Score That Chose the Split: XGBoost Regression, Explained

> *"XGBoost regression is Gradient Boosting with a smarter way of building each tree — and one small formula, $\frac{(\sum r)^2}{N+\lambda}$, sits at the centre of that smartness."*

You have already met Gradient Boosting: start with a rough guess, measure the mistakes, train a tree to correct them, repeat. XGBoost does **the same dance**. So what is actually new?

This chapter answers that, and it ends by answering the question you were carrying all along.

---

## 🎯 The Question This Whole Lecture Answers

> **"How does XGBoost use multiple decision trees, step by step, to predict a continuous value?"**

Notice what the lecture deliberately does *not* do. It does **not** ask you to memorise dozens of formulas. The deeper mathematical derivation is postponed to the next lecture. What you are meant to learn here is the **flow**: which step comes first, what each step produces, and what feeds the next one.

So if you ever feel lost in a number, return to the flow. The numbers can wait.

## 🧪 The Tiny Problem

The teacher's example is deliberately small: one input feature (**CGPA**), one continuous target (**Package in LPA**).

| CGPA | Package (LPA) |
|------|---------------|
| 6.7 | 4.5 |
| 9.0 | 11 |
| 7.5 | 6 |
| *(a fourth student)* | 8 |

**Goal:** give XGBoost a student's CGPA and get back their expected package.

The data is somewhat non-linear, which is exactly why it makes a good demonstration.

> ⚠️ **A note on the table you pasted.** The fourth row reads `9.0?`, and the split points the teacher uses (5.85, 7.1, 8.25) only make sense if that fourth CGPA is **5.0** (since 5.85 = (5.0 + 6.7) / 2). Two students at exactly 9.0 would not produce the threshold 5.85. I cannot confirm what the teacher wrote on the board, so **this chapter assumes the fourth student is CGPA 5.0 → 8 LPA**. Every number below is built on that assumption and was re-computed, not copied.

| CGPA | Package (LPA) |
|------|---------------|
| 5.0 *(assumed)* | 8 |
| 6.7 | 4.5 |
| 7.5 | 6 |
| 9.0 | 11 |

## 🧭 The Big Idea: It Is Still Gradient Boosting

The single most important sentence of the lecture:

> **XGBoost is essentially Gradient Boosting with many optimizations added for performance and speed.**

Read the skeleton slowly, because you will see it again and again:

```
Start with a base model
        ↓
Calculate errors
        ↓
Train a tree to correct those errors
        ↓
Add the tree
        ↓
Calculate new errors
        ↓
Train another tree
        ↓
Repeat
```

XGBoost follows this exact structure. The difference that this lecture focuses on is **how each tree is built**: instead of the usual criteria (variance reduction for regression, Gini or entropy for classification), XGBoost scores splits with a **Similarity Score**.

So remember:

$$\text{XGBoost} = \text{Gradient Boosting idea} + \text{special tree construction} + \text{lots of optimizations}$$

---

## 1️⃣ Stage One: Start With the Mean (and Admit It Is Weak)

Just like Gradient Boosting for regression, the first model is a flat guess: the mean of the target.

$$\text{Mean} = \frac{8 + 4.5 + 6 + 11}{4} = 7.375$$

*(The teacher rounds this to about 7.3. I use the exact 7.375 so the arithmetic stays checkable.)*

So the first model says: **every student → 7.375 LPA**.

Notice what this model ignores: **CGPA**. Whether the student has 5.0, 6.7, 7.5 or 9.0, the answer is identical. That is why it is obviously weak, and why it is a good starting point: there is a lot of room to improve.

### 📏 Then we measure the damage

$$\text{Residual} = \text{Actual} - \text{Current Prediction}$$

| CGPA | Actual | Prediction | Residual |
|------|--------|------------|----------|
| 5.0 | 8 | 7.375 | **+0.625** |
| 6.7 | 4.5 | 7.375 | **−2.875** |
| 7.5 | 6 | 7.375 | **−1.375** |
| 9.0 | 11 | 7.375 | **+3.625** |

A residual says: *"how wrong is the current model for this particular training example?"* In boosting vocabulary the teacher also calls these **pseudo-residuals**.

---

## 2️⃣ Stage Two: The Next Tree Does Not Predict Package

> 💭 *"Wait… if I am predicting salary, why would the next tree not predict salary?"*

This is the heart of boosting, and it is easy to miss:

```
Input  = CGPA
Target = Residual        ← NOT the package
```

The second tree is learning: **"Given this CGPA, what correction should I apply to the current prediction?"**

- Where the current prediction is **too low**, the residual is positive → the tree learns to **add**.
- Where it is **too high**, the residual is negative → the tree learns to **subtract**.

> 💭 *"Why does predicting the error help at all?"*

Suppose the model says 7.375 but the truth is 11. The residual is +3.625. A tree that learns *"around this CGPA region, add about 3.6"* has just given the model a **correction system**.

### 🧱 The model becomes a sum of corrections

$$F_1(x) = \text{mean}$$
$$F_2(x) = F_1(x) + \eta\, T_1(x)$$
$$F_3(x) = F_2(x) + \eta\, T_2(x)$$

and eventually:

$$\boxed{\text{Prediction} = \text{Base} + \eta T_1(x) + \eta T_2(x) + \eta T_3(x) + \cdots}$$

```
Tree 0 → rough guess
Tree 1 → correction
Tree 2 → another correction
Tree 3 → another correction
   ...
rough guess + many small corrections = strong prediction
```

---

## 3️⃣ But This Is Where XGBoost's Tree Becomes Special

In an ordinary regression tree, a split is judged by squared error / variance reduction. In an ordinary classification tree, by Gini or entropy.

XGBoost introduces a different judge:

$$\boxed{\text{Similarity Score} = \frac{\left(\sum \text{Residual}\right)^2}{\text{Number of Residuals} + \lambda}}$$

Where:

- **Residual** = the errors currently being corrected
- **Number of Residuals** = how many samples are in that leaf
- **$\lambda$** = a regularization parameter

For this lecture the teacher sets **$\lambda = 0$** to keep things simple. Its real purpose is saved for the regularization discussion.

### 🔍 What is it really measuring?

> 💭 *"Why is it called 'similarity' when it adds up the residuals?"*

Watch two leaves:

| Leaf contents | Sum | Squared | Score (λ=0) |
|---|---|---|---|
| +3, +4, +5 | 12 | 144 | 144 / 3 = **48** |
| +3, −3 | 0 | 0 | 0 / 2 = **0** |

Residuals that point in the **same direction reinforce each other**. Residuals that point in **opposite directions cancel**.

```
Similar residual directions → big sum → big score
Opposing residuals          → cancellation → small score
```

So a leaf with a high score is a leaf whose residuals **agree** about the correction needed. That is exactly the kind of leaf you want: one where a single correction number is a good fit for everybody inside it.

---

## 4️⃣ Searching for the Best Split

First, put **everything in one leaf** (the root) and compute its score. That is the **parent score**. Then ask: *can I split these residuals into groups that are more coherent?*

### Step 1: Sort the feature and form candidate thresholds

Sorted CGPA: `5.0, 6.7, 7.5, 9.0`. Candidates are the midpoints of neighbours:

$$\frac{5.0+6.7}{2} = 5.85 \qquad \frac{6.7+7.5}{2} = 7.1 \qquad \frac{7.5+9.0}{2} = 8.25$$

```
5.0 ──── 6.7 ──── 7.5 ──── 9.0
     ↓        ↓        ↓
   5.85      7.1     8.25
```

### Step 2: Score the left and right children of each candidate

$$\boxed{\text{Gain} = SS_{\text{left}} + SS_{\text{right}} - SS_{\text{parent}}}$$

Residuals in CGPA order: `+0.625, −2.875, −1.375, +3.625`. Their sum is **0**, so the **parent score is 0**.

| Split | Left residuals | $SS_L$ | Right residuals | $SS_R$ | Gain |
|---|---|---|---|---|---|
| CGPA < 5.85 | +0.625 | 0.3906 | −2.875, −1.375, +3.625 | 0.1302 | **0.5208** |
| CGPA < 7.1 | +0.625, −2.875 | 2.5313 | −1.375, +3.625 | 2.5313 | **5.0625** |
| CGPA < 8.25 | +0.625, −2.875, −1.375 | 4.3802 | +3.625 | 13.1406 | **17.5208** |

*(Example: for CGPA < 8.25 the left sum is −3.625, so $SS_L = 3.625^2 / 3 = 4.3802$. The right leaf has the single residual 3.625, so $SS_R = 3.625^2 / 1 = 13.1406$.)*

**Winner: CGPA < 8.25**, with the highest gain.

> 💭 *"Why not just pick the split whose single leaf has the biggest score?"*

Because a split produces **two** groups, and what you care about is the combined usefulness of both, compared against what you already had. That is why the formula is $SS_L + SS_R - SS_{\text{parent}}$.

### Step 3: Recurse

```
              CGPA < 8.25 ?
               /        \
            YES          NO
             │            │
  {+0.625, −2.875, −1.375}   {+3.625}  ← one sample, nothing to split
```

The right side has one sample, so it stops. The left side can be split again, using the remaining thresholds:

| Split of the left node | $SS_L$ | $SS_R$ | Parent (left node) | Gain |
|---|---|---|---|---|
| CGPA < 5.85 | 0.3906 | 9.0313 | 4.3802 | **5.0417** |
| CGPA < 7.1 | 2.5313 | 1.8906 | 4.3802 | **0.0417** |

**Winner: CGPA < 5.85.**

### 🛑 When do we stop?

Keep splitting forever and the tree memorises the training data: **overfitting**. The teacher stops at **maximum depth 2** in this hand-worked example. (He also notes that XGBoost's default depth differs from this tiny demonstration.)

```
More depth → more complex tree → fits training data more closely → risk of overfitting
```

---

## 5️⃣ What Does Each Leaf Say?

Another difference from ordinary trees: how a leaf's output is computed.

$$\boxed{\text{Output} = \frac{\sum \text{Residual}}{\text{Number of Residuals} + \lambda}}$$

With $\lambda = 0$ this collapses to something you already know:

$$\text{Output} = \text{Average residual}$$

The finished tree:

```
                CGPA < 8.25 ?
                 /         \
              YES           NO
              /               \
       CGPA < 5.85 ?        Leaf: +3.625
         /      \
   Leaf: +0.625   Leaf: −2.125
                  (average of −2.875 and −1.375)
```

> ⚠️ These leaf values are **corrections**, not package predictions. That distinction is critical.

---

## 6️⃣ Adding the Correction (and Why We Shrink It)

$$\boxed{\text{New Prediction} = \text{Old Prediction} + \eta \times \text{Tree Output}}$$

Here $\eta$ is the **learning rate** (shrinkage). With $\eta = 0.3$:

| CGPA | Old | Leaf output | $0.3 \times$ output | New prediction |
|------|-----|-------------|---------------------|----------------|
| 5.0 | 7.375 | +0.625 | +0.1875 | **7.5625** |
| 6.7 | 7.375 | −2.125 | −0.6375 | **6.7375** |
| 7.5 | 7.375 | −2.125 | −0.6375 | **6.7375** |
| 9.0 | 7.375 | +3.625 | +1.0875 | **8.4625** |

### 📉 New residuals

| CGPA | Old residual | New residual |
|------|--------------|--------------|
| 5.0 | +0.625 | **+0.4375** |
| 6.7 | −2.875 | **−2.2375** |
| 7.5 | −1.375 | **−0.7375** |
| 9.0 | +3.625 | **+2.5375** |

Every residual moved **closer to zero**. The model improved.

> 💭 *"Why is residual → 0 the goal?"*

Because $\text{Residual} = \text{Actual} - \text{Prediction}$. If it shrinks to 0, then $\text{Prediction} \approx \text{Actual}$. Large residual means a poor prediction; small residual means an improving one.

> 💭 *"Why do we need a learning rate at all?"*

Without shrinkage, a tree could apply a huge correction in one step. With $\eta = 0.1$, "add 5" becomes "add 0.5". Many small steps instead of a few large ones is **gradual learning**. The detailed treatment of shrinkage is left for later in the lecture series.

You might also notice that 6.7 and 7.5 received the **same** prediction. Both fell into the same leaf, and with depth 2 and this data the tree cannot separate them. More trees (or more depth) would.

## 7️⃣ Repeat: The Stages Pile Up

```
Stage 1:  Mean                      → residuals
Stage 2:  Tree 1 learns residuals   → new predictions → new residuals
Stage 3:  Tree 2 learns new residuals → ...
Stage 4:  Tree 3 learns new residuals → ...
```

Conceptually: $\text{Mean} + \eta\,DT_1 + \eta\,DT_2 + \cdots$

Re-running this with three trees (same settings, verified with real XGBoost, see the fact-check below):

| CGPA | Mean only | After 1 tree | After 2 trees | After 3 trees | Actual |
|------|-----------|--------------|---------------|---------------|--------|
| 5.0 | 7.375 | 7.5625 | 7.6938 | 7.7856 | 8 |
| 6.7 | 7.375 | 6.7375 | 6.2913 | 5.9789 | 4.5 |
| 7.5 | 7.375 | 6.7375 | 6.2913 | 5.9789 | 6 |
| 9.0 | 7.375 | 8.4625 | 9.2238 | 9.7566 | 11 |

Each column creeps toward the actual values.

### 🔢 What does `n_estimators` mean?

> 💭 *"What is `n_estimators`, actually?"*

How many boosting trees you want to **add**. `n_estimators = 100` means: base model + Tree 1 + Tree 2 + … + Tree 100.

### 🧮 How is a brand-new student predicted?

> 💭 *"A new student walks in with CGPA 6.7. Which tree answers?"*

**All of them**, in order. The base model gives 7.375; each tree routes 6.7 down to a leaf and contributes $\eta \times \text{leaf}$; you add everything:

$$\boxed{\text{Prediction} = \text{Base} + \eta\,\text{Tree}_1(x) + \eta\,\text{Tree}_2(x) + \eta\,\text{Tree}_3(x) + \cdots}$$

With our three trees, CGPA 6.7 gives **5.9789**.

### 🔑 The subtlety you must not miss

Each new tree does **not** restart from zero. If the current prediction is 7.5, the next tree does not say *"the answer is 8"*. It says *"you are still off by about +0.5 here"*. The model is constantly **refining the existing prediction**.

## 8️⃣ The Whole Pipeline in One Picture

```
TRAINING DATA
     ↓
Start with the mean
     ↓
Make initial predictions
     ↓
Calculate residuals
     ↓
Build an XGBoost tree on the residuals
     ↓
Find candidate splits
     ↓
Calculate Similarity Score
     ↓
Calculate Gain
     ↓
Choose the best split
     ↓
Build leaves → Calculate leaf output
     ↓
Multiply by learning rate and add to previous model
     ↓
Calculate new residuals
     ↓
Build another tree → Repeat
     ↓
Final boosted model
```

### 🧠 The mental model

Don't think *"Tree 2 predicts the package."* Think:

- **Tree 2 predicts how Tree 1 is wrong.**
- **Tree 3 predicts how the combined model is still wrong.**
- **Tree 4 predicts how the newer combined model is still wrong.**

### 🆚 Versus Random Forest

```
Random Forest                          XGBoost
Tree 1 ──┐                             Base prediction
Tree 2 ──┤                                  ↓
Tree 3 ──┼─→ combine predictions        Tree 1 → correct errors
Tree 4 ──┤                                  ↓
Tree 5 ──┘                             Tree 2 → correct remaining errors
                                            ↓
Trees are largely independent          Tree 3 → ...
                                       Trees are built sequentially
```

Random Forest = **bagging**. XGBoost = **boosting**.

### 👥 The four-estimators story

1. Person 1: *"I'll just predict the average salary."* (wrong for most)
2. Person 2: *"For this CGPA region we are underpredicting."* → correction
3. Person 3: *"Still some error here."* → another correction
4. Person 4: *"Still a little wrong."* → another correction

Initial guess + correction + correction + correction + … = boosting.

## 📌 The Three Formulas to Remember From the Lecture

| Name | Formula |
|---|---|
| Similarity Score | $SS = \dfrac{(\sum \text{Residual})^2}{N + \lambda}$ |
| Gain | $\text{Gain} = SS_L + SS_R - SS_{\text{Parent}}$ |
| Leaf Output | $\text{Output} = \dfrac{\sum \text{Residual}}{N + \lambda}$ |

And the one sentence never to forget:

> **Every new XGBoost tree tries to correct the mistakes left by the model built so far.**

### 🔟 The lecture in ten lines (for revision)

1. XGBoost regression follows the Gradient Boosting idea.
2. Start with the mean of the target.
3. Residual = actual − prediction.
4. Train a tree on the feature(s) to predict those residuals.
5. XGBoost builds that tree using the Similarity Score.
6. Try possible splits and calculate Gain.
7. Choose the split with maximum Gain.
8. Each leaf gets an output based on its residuals.
9. Add the learning-rate-scaled output to the previous prediction.
10. Repeat with new residuals until you reach the chosen number of trees.

---

## 🌉 ML Bridge

The pattern you just learned is the template for almost every modern tabular-ML model:

- **Gradient Boosting (previous chapters):** correct mistakes with trees; leaf = mean residual.
- **XGBoost:** same loop, but the tree is scored by an objective that includes complexity cost.
- **Next steps:** classification uses the same machinery with different $g$ and $h$ (log-loss instead of squared error), and libraries like LightGBM and CatBoost follow the same overall plan with their own engineering choices.

When you later tune `reg_lambda`, `gamma`, `learning_rate` and `n_estimators`, you will no longer be turning mysterious dials. You will know which term of the objective each one touches.

---

## 🌀 Deepest Realization

> The residual is not just "the error." It is the **gradient of the loss** (with a minus sign), and the Similarity Score is **how much the objective would drop if one leaf absorbed those gradients together.** XGBoost is not a collection of tricks around a decision tree. It is a decision tree whose every choice (where to split, what to output, when to stop) is answered by one equation.

---

## ✅ Final Takeaway

> *"Start with a rough guess, let each tree learn only what the model still gets wrong, and let one derived score, $\frac{(\sum r)^2}{N+\lambda}$, decide where to split, what each leaf says, and when to stop. That single formula is why XGBoost can be regularized, pruned, fast and flexible all at once."*
